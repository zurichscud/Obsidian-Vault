`<input>` 是 HTML 表单中最核心、最灵活的交互元素，用于接收用户的各种输入。它是一个**自闭合标签（空元素）**，形态和功能完全由 `type` 属性决定（默认为 `text`）。

## 1. 核心 `type` 类型分类

| **类别**    | **type 值**         | **作用与特点**                                              |
| --------- | ------------------ | ------------------------------------------------------ |
| **文本类**   | `text`             | 单行纯文本输入框（默认值）。                                         |
|           | `password`         | 密码框，输入内容会被遮掩为圆点或星号。                                    |
|           | `email`            | 邮箱输入，自带基础的邮箱格式校验，移动端会调出带 `@` 的键盘。                      |
|           | `tel`              | 电话号码，移动端会调出数字拨号键盘（本身无格式校验）。                            |
|           | `url`              | 网址输入，提交时校验是否包含协议头（如 `https://`）。                       |
|           | `search`           | 搜索框，部分浏览器会在右侧提供一键清空的小叉号 `×`。                           |
| **选择类**   | `checkbox`         | **复选框**，允许用户从多个选项中选择零个、一个或多个。                          |
|           | `radio`            | **单选按钮**，同一 `name` 属性下的多个选项只能选中一个。                     |
| **数值与日期** | `number`           | 数字输入框，带有上下微调箭头，支持限制最大值和最小值。                            |
|           | `range`            | 滑动条，适用于不需要精确数值的调节（如音量、亮度）。                             |
|           | `date` / `time`    | 原生日期选择器 / 时间选择器（此外还有 `datetime-local`、`month`、`week`）。 |
|           | `color`            | 原生取色器，返回十六进制颜色值（如 `#ff0000`）。                          |
| **文件与操作** | `file`             | 文件上传控件，配合 `accept` 限制文件类型，`multiple` 支持多选。             |
|           | `submit` / `reset` | 提交当前 `<form>` 表单 / 重置表单内所有控件为初始值。                      |
|           | `button`           | 普通可点击按钮，无默认行为，通常绑定 JS 事件。                              |
|           | `hidden`           | **隐藏域**，页面不可见，常用于在表单提交时携带 Token 或数据 ID。                |

## 2. 常用关键属性

除了 `type`，以下属性在日常开发中高频使用。

### 2.1 标识与数据

- `name`：表单提交时的**键名**（没有 `name` 的字段在原生表单提交时会被忽略）。
- `value`：控件的当前值（对于 `radio` 和 `checkbox`，代表选中后提交的值）。

### 2.2 交互与提示

- `placeholder`：占位符提示文本，用户输入后自动消失。
- `autofocus`：页面加载完成后自动获取焦点。
- `autocomplete`：控制浏览器的自动填充行为（如 `off`、`on`、`new-password`）。

### 2.3 状态控制

- `disabled`：**禁用状态**。不可点击、不可聚焦，且**不会随表单提交**。
- `readonly`：**只读状态**。不可修改，但可以聚焦、选中复制，且**会随表单提交**。

### 2.4 原生表单校验

- `required`：必填项，为空时阻止表单提交并弹出提示。
- `min` / `max` / `step`：限制 `number`、`range` 或日期的最小值、最大值和步长。
- `minlength` / `maxlength`：限制文本输入的最小和最大字符长度。
- `pattern`：接收一个正则表达式，用于自定义输入格式的校验规则。

## 3.2 input与change事件

在原生 DOM 中，`input` 和 `change` 事件有明显区别：

- `input` 事件：每次键盘敲击、粘贴或内容变化时**实时触发**。
- `change` 事件：对于文本类输入框，仅在**失去焦点且内容发生改变**时触发；对于 `radio`、`checkbox`、`file` 则在状态改变时立即触发。

## 3. 最佳实践

### 3.1 务必搭配 `<label>` 使用

通过 `for` 属性绑定 `<input>` 的 `id`（或直接用 `<label>` 包裹 `<input>`）。这不仅对屏幕阅读器（无障碍访问）至关重要，还能扩大点击区域——尤其是单选框和复选框，点击文字即可选中。

下面的示例用 `<label>` 包裹了一个复选框：

```html
<label for="agree">
  <input type="checkbox" id="agree" name="agree" /> 我已阅读并同意协议
</label>
```


### 3.3 中文输入法（IME）合成问题

监听 `input` 事件做实时搜索或输入过滤时，拼音输入法在“敲拼音但未选词上屏”阶段也会触发 `input` 事件。如果需要等用户选词确认后再处理，需要配合监听 `compositionstart` 和 `compositionend` 事件。

### 3.4 移动端键盘优化（`inputmode`）

有时需要输入纯数字（如短信验证码），但不想用 `type="number"`（因为它会带上下箭头，且会忽略前导零如 `0123`）。此时推荐用 `type="text"` 搭配 `inputmode="numeric"`，既能保持文本特性，又能让手机弹出纯数字键盘。
