---
title: "请求头语法"
---

请求头（Request Headers）主要是给服务器（Server）看的。

## 1. 分隔符

请求头的值由逗号与分号分隔，两种分隔符的作用与语义如下：

| 分隔符 | 作用 | 语义 |
| -------- | -------------------------- | ------------------------- |
| 逗号 `,` | 分隔**多个独立的值**（列表） | “我要 A、B、C 中任意一个” |
| 分号 `;` | 分隔**某个值的参数/属性** | 附属于紧邻前面的那个值 |

## 2. 值的结构

一个请求头的值由逗号分隔成多个值，每个值可以用分号附带参数。通用结构如下：

```
值1;参数1;参数2,
值2;参数1;参数2,
值3;参数1;参数2
```

## 3. 示例

以 `Accept-Language` 请求头为例：

```
Accept-Language: zh-CN,zh;q=0.9,en;q=0.8
```

这个请求头实际上表达的是：

```
[
{ value: "zh-CN" },
{ value: "zh", q: 0.9 },
{ value: "en", q: 0.8 }
]
```

## 4. 禁止修改的请求头

W3C 和浏览器规范将 `Origin`、`Referer`、`Cookie`、`Host` 等对安全至关重要的请求头列为了 **“被禁止修改的请求头”**。这些头只能由浏览器自动控制，JS 没有任何修改权限。

例如，下面的代码尝试在 `fetch` 中设置 `Origin`：

```js
// 浏览器会直接报错，或者忽略这行代码
fetch('http://api.example.com/data', {
  headers: {
    'Origin': 'http://hacker.com'
  }
});
```

## 5. 常见请求头

### 5.1 身份验证

`Authorization`

例如：`Authorization: Bearer <token>`，后端会读取这个头，解析里面的 JWT Token，判断当前用户是谁、有没有权限访问这个接口。

### 5.2 请求体描述

`Content-Type`、`Content-Length`

例如：`Content-Type: application/json`，告诉 Java 后端：“我的 Body 里面装的是 JSON 数据”。

### 5.3 内容协商

告诉服务器希望返回什么内容给客户端。

`Accept`、`Accept-Language`、`Accept-Encoding`

例如：`Accept: application/json`，告诉服务器：“我前端只要 JSON 格式的返回值，别给我返回一堆 HTML 页面。”

### Referer

- `Referer` 用来表示当前请求是从哪个页面跳转或发起的。
- 只要是浏览器发起的请求，`Referer` 都会添加到请求头中。
- `Referer` 包含完整的**协议、域名、端口、路径以及查询参数**，例如：

```
https://juejin.cn/post/123456789?from=sidebar
```
