`Host` 是根据请求 URL 自动生成的。

## 1. 什么是 Host 头

`Host` 是 HTTP 请求头，用于告诉服务器：客户端当前请求的是哪个主机（域名）以及端口。

它是 HTTP/1.1 中非常重要的请求头，主要用于解决一台服务器部署多个网站时，服务器如何区分请求目标的问题。

```http
GET /index.html HTTP/1.1
Host: www.example.com
```

## 2. 为什么需要 Host

**在实际通过网络传输的 HTTP 原始报文中，请求行里的 URL 根本不包含域名。**

你在浏览器地址栏里看到完整 URL，只是客户端展示和解析的入口。当浏览器真正把数据打包发给服务器时，底层报文并非直接把地址栏里的字符串原样塞进去。

请求 `https://api.example.com/users/list?id=1` 时，浏览器在底层做的事情是：

**1. DNS 阶段（客户端与 DNS 服务器交互）**

- 浏览器拿到 URL 里的域名 `api.example.com`，询问 DNS 服务器：_“这个域名对应的 IP 是多少？”_
- DNS 回复：_“IP 是 `198.51.100.1`。”_
- **此时 DNS 的任务彻底结束。**

**2. TCP 连接阶段（客户端与目标服务器交互）**

- 浏览器根据拿到的 IP，向 `198.51.100.1` 建立 TCP 三次握手。
- **注意**：TCP 协议头里只有两端的目标 IP 和端口（例如 `198.51.100.1:80`），**TCP 报文根本不包含任何域名信息**。

**3. HTTP 阶段（目标服务器开始看内容）**

- TCP 通道通了之后，服务器只知道：_“有人连上了我的 80 端口，并扔给我一段字节流。”_
- 如果 HTTP 报文长这样：

```http
GET /index.html HTTP/1.1
```

此时服务器懵了：这台机器上绑定了 5 个域名（`site-a.com`、`site-b.com`、`site-c.com`），都指向这个 IP。**服务器完全不知道你刚才找 DNS 查的是哪个域名。**

## 3. 如何发送 Host

`Host` 头是由**发起 HTTP 请求的客户端程序**（HTTP Client）负责生成的，我们无需介入。
