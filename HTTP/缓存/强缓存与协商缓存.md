## 1. 强缓存

### 1.1 定义

**强缓存**是 HTTP 缓存体系中最快的一种机制。当客户端请求某个资源时，浏览器会先检查本地缓存；一旦命中强缓存，**浏览器完全不向服务器发送任何网络请求**，而是直接从本地内存或硬盘中读取资源。

### 1.2 命中表现

在浏览器开发者工具的 Network 面板中，强缓存通常体现为：

- 状态码显示为 `200 OK`
- Size 列显示为 `(from memory cache)` 或 `(from disk cache)`
- Time 列耗时通常为 **0 ms**

### 1.3 控制字段与优先级

强缓存完全由服务端在资源初次下发时的响应头控制，主要涉及两个字段：

| 响应头字段 | 引入规范 | 核心机制 | 特点 / 缺点 |
| --- | --- | --- | --- |
| `Cache-Control: max-age=<seconds>` | HTTP/1.1（现代标准） | **相对时间**（秒），表示资源自获取后的有效时长。例如 `max-age=31536000` 表示一年内有效。 | **绝对优先**，不受客户端系统时间偏差影响。 |
| `Expires` | HTTP/1.0（历史遗留） | **绝对时间**（GMT 格式时间戳）。例如 `Expires: Wed, 21 Oct 2026 07:28:00 GMT`。 | 容易受客户端本地系统时间被篡改或不准确的影响，可能导致缓存**提前失效或长期不失效**。 |

当 `Cache-Control` 的 `max-age` 与 `Expires` 同时存在时，`Cache-Control` **具有更高优先级**，`Expires` 会被直接忽略。

### 1.4 判断流程

1. **发起请求**：用户在页面中加载静态文件（如 `<script src="bundle.js">`）或进行路由跳转。
2. **检查新鲜度**：
    - 计算该资源在本地的“年龄”（当前时间 - 资源接收时间）。
    - 对比响应头中的 `max-age`。
3. **分流处理**：
    - **未过期（命中强缓存）**：直接从内存或磁盘读取文件，返回 `200 (from cache)`，**网络请求数为 0**。
    - **已过期（强缓存失效）**：浏览器带着上次的 `ETag` 或 `Last-Modified` 向服务器发起网络请求，**进入协商缓存流程**。

## 2. 协商缓存

### 2.1 机制

当强缓存失效（超过 `max-age`）或被显式跳过（配置了 `Cache-Control: no-cache`）时，客户端不会盲目下载完整资源，而是携带**缓存标识**向服务器发起“询问”。

如果资源未变动，服务器返回轻量的 `304 Not Modified`，通知客户端直接复用本地文件；若已变动，则返回 `200 OK` 并下发全新内容。

协商缓存由两对标头协同工作。

### 2.2 方案一：ETag 与 If-None-Match（内容指纹）

`ETag`（Entity Tag）是服务器根据文件内容计算出的**唯一哈希/特征标识符**。

**初次获取**：服务器返回资源，并在响应头中附带 `ETag`：

```http
HTTP/1.1 200 OK
ETag: "w/1a2b3c4d"
```

**再次请求**：本地强缓存失效后，浏览器自动将该值填入 `If-None-Match` 请求头发送：

```http
GET /app.js HTTP/1.1
Host: example.com
If-None-Match: "w/1a2b3c4d"
```

**服务端校验**：服务器计算当前资源的最新 ETag。若一致则返回 `304 Not Modified`；若不一致则返回 `200 OK` 及新 ETag 与内容。

> **强 ETag 与弱 ETag**
>
> - **强 ETag**（如 `"abc"`）：要求字节级完全一致。
> - **弱 ETag**（如 `W/"abc"`）：前缀带 `W/`，仅要求语义等价，允许细微字节差异（常用于压缩转换场景）。

### 2.3 方案二：Last-Modified 与 If-Modified-Since（时间戳）

`Last-Modified` 记录资源在服务器操作系统上的**最后修改时间**。

**初次获取**：服务器通过响应头返回资源的最后修改时间：

```http
HTTP/1.1 200 OK
Last-Modified: Fri, 23 Oct 2026 09:30:00 GMT
```

**再次请求**：强缓存失效后，浏览器自动把该时间作为 `If-Modified-Since` 发送：

```http
GET /logo.png HTTP/1.1
Host: example.com
If-Modified-Since: Fri, 23 Oct 2026 09:30:00 GMT
```

**服务端校验**：服务器判断该时间之后文件是否改动。未改动返回 `304`，改动返回 `200`。

### 2.4 最佳实践

两者可以同时配置。服务端收到请求时，会优先比对 `If-None-Match`；两者均满足时，才视为未修改并返回 `304`。
