## 1. 概念与架构

**反向代理（Reverse Proxy）** 位于客户端和后端真实服务器之间。客户端向反向代理发送请求，反向代理根据配置将请求转发给内部网络的一台或多台源服务器，再将获取的响应返回给客户端。

对于客户端而言，反向代理就如同目标服务器本身，客户端无需也无法直接感知后端源服务器的存在与真实 IP。

## 2. 核心功能与应用场景

### 2.1 负载均衡（Load Balancing）

将海量客户端请求通过特定策略（轮询 Round-Robin、权重 Weight、IP Hash、最少连接数）分发到后端的各个应用实例，避免单点过载，支持横向扩展。

### 2.2 动静分离与缓存加速

- 静态资源（HTML、JS、CSS、图片）直接由反向代理（如 Nginx）本地读取并返回，或配置 HTTP 缓存策略；
- 动态 API 请求（如 `/api/*`）才转发给后端应用服务器（如 Spring Boot、Express），大幅削减应用服务器的压力。

### 2.3 安全防护与隐藏源站

- 后端服务器部署在内网或 VPC 私有子网中，不开放公网 IP，外部流量只能经过反向代理。
- 集中防御恶意流量。

### 2.4 SSL统一管理

- 在反向代理统一配置 HTTPS 证书，负责加解密握手计算；
- 代理与内网集群之间使用普通 HTTP 或轻量通信，减轻后端业务服务器的 CPU 开销，并且证书更新时只需在一处维护。

### 2.5 路由重写与统一网关

- 解决前后端跨域（CORS）问题：统一对外暴露单域名（如 `https://example.com`），根据路径将 `/api` 转到后端服务，前端静态页托管在 `/`。
- 支持灰度发布、蓝绿发布（按照 Header/Cookie 或权重分流到新旧版本服务）。
