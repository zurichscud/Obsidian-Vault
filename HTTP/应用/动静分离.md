## 1. 基本概念

将动态资源与静态资源分开处理和分发。

### 1.1 资源分类

- 动态资源：如动态网页、API 请求
- 静态资源：HTML、CSS、JavaScript、图像文件

### 1.2 实现方式

- 使用反向代理服务器（如 Nginx）将静态请求和动态请求转发到不同的后端服务器或服务。
- 将静态资源部署到 CDN 上，通过 CDN 分发静态资源，减轻源服务器的负载。
- 使用专门的静态文件服务器（如 Amazon S3、Google Cloud Storage）存储和提供静态资源，而将动态请求交给应用服务器处理。

## 2. 未做动静分离的 Express 模式

以下代码为典型的单体全包写法：Node.js 进程同时负责静态资源 I/O 与动态 API 业务。

```js
import express from 'express';
import path from 'path';

const app = express();

// 1. 静态资源：由 Express 自身读取磁盘并输出
app.use('/static', express.static(path.join(process.cwd(), 'public')));

// 2. 动态接口：业务逻辑计算、数据库操作
app.get('/api/users', async (req, res) => {
  // 模拟从数据库查数据
  const users = [{ id: 1, name: 'Alice' }, { id: 2, name: 'Bob' }];
  res.json({ success: true, data: users });
});

app.listen(3000, () => {
  console.log('Server running on port 3000');
});
```

### 2.1 生产环境不推荐的原因

1. **拖慢 API**：静态文件的流传输（Stream）、TCP 读写和内存缓冲同样占用主线程，高并发下 API 响应会被拖慢。
2. **效率不如 Nginx**：Nginx 借助内核的 `sendfile()` 零拷贝机制传文件，Node.js 优化再多也比不过。
3. **扩容不划算**：静态流量涨了就加 Node.js 实例，相当于花大价钱做简单的静态分发。

## 3. 实现方案

### 3.1 Nginx + Express

让 Express **完全卸掉静态资源托管的担子**，只做纯粹的 RESTful API 服务，静态文件交给前面的 Nginx 处理。

以下代码为卸掉静态资源托管后的 Express 服务，只保留 API 接口：

```js
import express from 'express';

const app = express();
app.use(express.json());

// 只有 API 接口
app.get('/api/v1/posts', (req, res) => {
  res.json({ code: 0, list: [] });
});

app.listen(3000, '127.0.0.1', () => {
  console.log('API Service listening on 127.0.0.1:3000');
});
```

以下 Nginx 配置按路径把静态资源与 API 请求分流：

```nginx
server {
    listen 80;
    server_name myapp.com;

    # ---------------- 静态资源部分 ----------------
    # 静态静态构建包（HTML, JS, CSS, 图片）直接由 Nginx 零拷贝返回
    location /static/ {
        alias /var/www/myapp/dist/;
        expires 30d;
        add_header Cache-Control "public, immutable";
        access_log off; # 关闭静态资源日志，提升吞吐
    }

    # 前端 SPA (Vue/React) 单页路由 Fallback
    location / {
        root /var/www/myapp/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # ---------------- 动态 API 部分 ----------------
    # 仅将 /api/ 转发给内网 Express 进程
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        
        # 传递真实客户端信息
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 3.2 OSS + CDN + Express

在中大型项目中，静态文件甚至不需要放在这台服务器的磁盘上。

前端构建产物 (dist) ──> 上传至 OSS / S3 ──> 挂载 CDN (https://cdn.example.com)  
Express 部署在云主机/容器 ──> 提供纯接口 (https://api.example.com)

在 Express 里，你需要处理的关键变化是**跨域 (CORS)**。以下代码演示通过 `cors` 中间件放行跨域请求：

```js
import express from 'express';
import cors from 'cors';

const app = express();

// 静态页面在 cdn.example.com 打开，请求 api.example.com 时触发跨域
app.use(cors({
  origin: ['https://cdn.example.com', 'https://example.com'],
  credentials: true,
  methods: ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS']
}));

app.get('/api/data', (req, res) => {
  res.json({ message: 'Hello from isolated Express API' });
});

app.listen(3000);
```

资源访问路径从 `https://example.com/abc.js` 变成了 `https://cdn.example.com/abc.js`。
