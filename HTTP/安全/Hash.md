---
title: 哈希函数
---

哈希函数是一种**把任意长度数据 → 固定长度输出**的算法。

## 1. 特点

### 1.1 固定长度输出

无论输入多长，输出长度固定。例如：

- SHA256 → 256 位（32 字节）
- MD5 → 128 位（16 字节）

### 1.2 不可逆

无法从哈希值反推出原始数据。

```text
A → hash
但不能 hash → A
```

### 1.3 雪崩效应

输入哪怕改一个字符，结果都会完全不同。

以 `hello` 与 `hellO` 为例：

```text
hello
→ 2cf24d...

hellO
→ 872e4e...
```

### 1.4 一致性

相同的输入，相同的算法，必定具有相同的输出。

## 2. 常见哈希算法

| 算法   | 长度（HEX） | 是否安全  | 说明     |
| ------ | ----------- | --------- | -------- |
| MD5    | 32          | ❌ 不安全 | 已被破解 |
| SHA256 | 64          | ✅ 安全   | 常用     |
| SHA512 | 128         | ✅ 安全   | 更强     |

## 3. 哈希是不安全的

虽然哈希值不可逆，但是哈希具有一致性，因此通过暴力枚举，就有可能得到原始值。

因为哈希输出是**固定长度**，而输入是**无限可能**。当输入数量超过输出空间，就一定会出现碰撞（哈希碰撞）。（例如 SHA256 只有 2²⁵⁶ 种结果）。

> 哈希碰撞在数学上必然存在，但在工程上可以忽略。

## 4. 应用

### 4.1 密码存储

数据库通常不会存储明文密码，会将原始密码转为哈希值存入数据库。

存储时的处理如下：

```text
password → hash → 存数据库
```

验证时，对输入密码做同样的哈希，再与数据库中的值对比：

```text
输入密码 → hash → 对比数据库
```

### 4.2 文件完整性校验

下载文件后，计算文件哈希并与官方哈希比对：

```text
文件 → 计算 hash
对比官方 hash
```

两者一致，说明文件未被篡改。

假设机械硬盘连续读取速度为 100～200 MB/s，使用 SHA-256：

|文件大小|预计耗时|
|---|---|
|1 MB|几毫秒|
|10 MB|0.05～0.1 秒|
|100 MB|0.5～1 秒|
|500 MB|2.5～5 秒|
|1 GB|5～10 秒|
|10 GB|50～100 秒|

## 5. bcrypt

bcrypt 是一种**专门用于密码存储的慢哈希算法**。bcrypt 设计目标不是“快速算出哈希”，而是“让破解变得非常慢”。

bcrypt 通常需要第三方库支持。

### 5.1 原理

bcrypt 哈希值的特点是加密后的字符串包含了加密时的**算法版本**、**成本因子**、**盐**、和最终得到的哈希值。

下面是一个 bcrypt 哈希值示例：

```text
$2a$10$7mG.bF32bv36IBLetWB11O6zMAXe9Zc5P7cTkfgqTol7yVspl37Va
```

它的结构如下：

```text
$算法版本$成本因子$盐值+哈希结果
```

- **算法版本**：表示 bcrypt 版本。
- **成本因子**：控制计算轮数，例如：

  ```text
  cost = 10 →2^10→ 1024 次运算
  cost = 12 →2^12→ 4096 次运算
  ```

- **盐**：bcrypt 会自动生成，并保存在 bcrypt 哈希值中。

### 5.2 工作流程

密码存储的流程：

```text
密码 → 加盐 → 多轮哈希 → 存储结果
```

验证密码的流程：

```text
输入密码 → 解析该账号的 bcrypt hash 中的 salt 和 cost → 重新计算 → 比较
```
