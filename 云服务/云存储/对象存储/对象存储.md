## 1. 概述

### 1.1 本质

对象存储是基于网络 API 的 Key-Value 存储系统，没有多层文件夹概念。数据被封装为“对象”，每个对象包含唯一标识、内容以及自定义元数据。

### 1.2 特点

- 不支持直接随机修改对象内部的某些字节，更新通常需要**覆盖整个对象**。
- 通过 RESTful API（GET/PUT/DELETE）直接走 HTTP 通信。
- 具备近乎无限的水平扩展能力与低廉的单位存储成本。

### 1.3 适用场景

- 海量非结构化数据（图片、音视频、安装包、备份归档）。
- 配合 CDN 构筑前端静态资源分发体系。
- 作为大数据分析与 AI 训练的原始数据湖。

## 2. 核心概念与数据模型

在对象存储中，数据被统一抽象为**对象**，存放在被称为存储桶的命名空间中。存储桶、对象、键与元数据之间的组织关系如下：

```
Bucket (全局或租户内唯一容器)
 └── Object: Key -> [ Data + Metadata ]
```

### 2.1 存储桶

存储桶是对象的容器，类似于数据库中的“库”。它通常用于权限隔离、配额控制、生命周期管理和跨区域复制配置。

### 2.2 键

键是对象在存储桶内的唯一标识字符串（如 `users/avatar/1001.png`）。虽然键中可以包含斜杠 `/`，但存储引擎**并不存在真实的层级目录结构**，仅通过前缀匹配模拟出目录视图。

### 2.3 数据体

数据体是被存储的原始二进制负载，支持从几字节到数十 TB 的单文件。

### 2.4 元数据

元数据是与数据绑定存放的一组属性，分为两类：

- **系统元数据**：如 `Content-Length`、`Content-Type`、`ETag`（通常为 MD5/哈希值）、`Last-Modified` 等。
- **用户自定义元数据**：以自定义 Header（如 `x-amz-meta-*`）形式持久化，常用于记录业务标签、租户 ID、上传者信息等。借助这些元数据即可完成初步校验，无需额外查询关系型数据库。

## 3. 关键特性与底层机制

### 3.1 扁平组织

对象通过**存储桶**和**键**定位，没有真实目录层级；目录视图仅由键前缀模拟。

### 3.2 访问接口：原生 RESTful API

对象存储不依赖操作系统内核的驱动或挂载协议（如 NFS、SMB），完全通过标准 HTTP/HTTPS 协议通信：

- `PUT /bucket/key`：上传对象。
- `GET /bucket/key`：下载对象。
- `HEAD /bucket/key`：仅读取元数据，不拉取数据负载。
- `DELETE /bucket/key`：删除对象。

### 3.3 写模型：原地修改受限

- **不可随机写入**：传统文件系统支持通过 `fseek` 定位到某个 offset 覆写几个字节，但对象存储**不支持原地修改**。哪怕只修改一个 1 GB 视频中的 1 秒内容，也必须重新 PUT 上传、覆盖整个对象。
- **追加写**：部分实现（如阿里云 OSS、MinIO 部分模式）支持通过 `AppendObject` 从尾部持续写入日志，但依然不能在中间插入或随机修改。

### 3.4 数据可靠性：多副本与纠删码

对象存储通常部署在由廉价商用服务器构成的超大规模集群上。其极高的数据持久性（通常宣称 99.999999999%，即 11 个 9）依赖底层的冗余策略：多副本机制与纠删码机制。

## 4. 分层存储

### 4.1 存储层级

对象存储根据数据热度分层存放，以降低存储成本：

| 层级 | 访问频度与用途 | 成本与取回特征 |
| --- | --- | --- |
| **标准** | 高频读写 | 读写费用低，存储费用基准 |
| **低频** | 长期保存、每季度访问几次 | 存储单价较低，但取回有流量费 |
| **归档/冷归档** | 合规备份数据 | 单价极低，读取前需要解冻，解冻耗时数分钟至数小时 |

### 4.2 写入时：显式指定或默认兜底

写入时的存储层级有两种确定方式：

- **显式指定**：上传请求头携带 `Storage-Class`（如 `ARCHIVE`），对象写入时即直接进入冷层，适用于确定的历史备份。
- **默认兜底（绝大多数情况）**：上传时不传任何参数，系统按存储桶默认设置，统一先存入**标准存储**。

### 4.3 写入后：存储引擎自动接管

对象存入后，由系统接管其生命周期：

- **时间驱动（生命周期规则）**：系统后台定时扫描，达到设定期限（如 30 天、90 天）后自动下沉至低频或归档，到期自动删除。
- **热度驱动（智能分层）**：系统自动监控访问频次，长期无人访问时自动降级以节省成本；一旦有人读取，毫秒级自动回捞。

## 5. 现代架构中的典型模式

### 5.1 客户端直传与预签名 URL

为避免应用服务器成为网络 I/O 瓶颈，生产环境通常采用客户端直传架构，流程如下：

1. **鉴权与授权**：客户端（前端/App）请求业务服务端获取上传凭证。
2. **生成签名**：服务端使用云存储的 `AccessKeySecret` 计算带有有效期的临时预签名 URL（或 STS Token）。
3. **直连上传**：客户端携带签名直接通过 HTTP `PUT` 将文件传输至对象存储，不消耗业务服务器的内网带宽和内存。
4. **事件回调**：对象存储上传完成后，通过消息队列（Kafka）或 HTTP Webhook 回调业务服务端完成落库记录。

### 5.2 动静分离与 CDN 加速

对象存储与内容分发网络（CDN）天然契合。存储桶设置为私有访问，仅授权 CDN 边缘节点的反向代理回源。

在对象存储前增加 CDN 缓存后，既能大幅降低对象存储的对外公网下行流量费用，又能解决远距离访问的高延迟问题。
