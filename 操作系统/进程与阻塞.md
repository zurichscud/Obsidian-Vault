进程（Process）是操作系统分配资源（如内存）的基本单位，

简单来说：进程是“壳子”和“资源仓库”，线程才是里面真正干活的“工人”。一个进程里至少有 1 个线程（主线程），也可以包含成百上千个线程。

## 1. 什么是进程（Process）

简单来说，一个正在运行的程序，就是一个进程。

### 1.1 常见例子

- 打开 Chrome，操作系统会创建相关进程。
- 启动一个 Node.js 服务，会创建一个 Node.js 进程。
- 启动一个 Java 程序，会创建一个 JVM 进程。

### 1.2 进程拥有的资源

一个进程通常拥有：

| 资源 | 说明 |
| --- | --- |
| 内存空间 | 独立的虚拟地址空间 |
| 代码段 | 存放程序代码 |
| 数据段 | 存放全局变量等 |
| 堆 | 动态分配内存 |
| 栈 | 存放函数调用信息 |
| 文件描述符 | 管理打开的文件、网络连接等 |
| 线程 | 执行程序指令的执行单元 |

## 2. 什么是阻塞（Blocking）

阻塞指的是：一个执行单元因为等待某个操作完成，暂时无法继续执行后续任务。

```js
console.log('开始');

const result = readFileSync('./test.txt');

console.log('结束');
```

这里的 `readFileSync` 是同步读取文件。

1. 输出「开始」。
2. 执行文件读取。
3. 等待文件读取完成。
4. 读取完成后，继续执行。
5. 输出「结束」。

在第 2～4 步期间，当前线程被阻塞。

## 3. 阻塞与非阻塞

阻塞与非阻塞的区别，是理解 Node.js 的关键。假设有两个任务：

- 任务 A：读取一个文件，需要 3 秒。
- 任务 B：输出一条日志。

### 3.1 同步阻塞

```js
const fs = require('fs');

console.log('A 开始');

const data = fs.readFileSync('./test.txt');

console.log('A 结束');

console.log('B 执行');
```

任务 A 必须完成，任务 B 才能执行。

### 3.2 异步非阻塞

```js
const fs = require('fs');

console.log('A 开始');

fs.readFile('./test.txt', (err, data) => {
  console.log('A 结束');
});

console.log('B 执行');
```

执行顺序：

```text
A 开始
B 执行
A 结束
```

任务 A 在等待文件读取时，主线程可以继续执行任务 B。

## 4. 单线程、并发与并行

Express 默认只有一个 JavaScript 主线程，但它可以通过事件循环（Event Loop）和非阻塞 I/O，在不创建多个 JavaScript 线程的情况下，同时处理多个用户的 HTTP 请求。

### 4.1 三个容易混淆的概念

- 单线程：指 JavaScript 代码默认由一个主线程执行。
- 并发：指多个任务可以在一段时间内交替推进。
- 并行：指多个任务在同一时刻真正执行。

Node.js 默认单线程，但不代表它只能处理一个请求。

## 5. Node.js 如何处理多个请求
### **Node.js 的线程结构**

![[Pasted image 20261118112826.png]]
- 一个普通 Node.js 程序通常运行在一个进程中。
    
- 这个进程有一个主线程，负责执行 JavaScript。
    
- 还可能有其他工作线程，例如 libuv 线程池中的线程。

### Express请求示例

假设有三个用户同时访问你的 Express 服务：

- 用户 A：请求数据库，需要等待 3 秒。
- 用户 B：请求一个文件，需要等待 2 秒。
- 用户 C：请求一个简单接口，只需要 10 毫秒。

```js
app.get('/user', async (req, res) => {
  const user = await db.query('SELECT * FROM users');
  res.json(user);
});

app.get('/file', async (req, res) => {
  const data = await fs.promises.readFile('./test.txt');
  res.send(data);
});

app.get('/hello', (req, res) => {
  res.send('Hello');
});
```

### 5.2 阻塞式思维下的执行顺序

如果按照传统的阻塞式思维，执行过程大致如下：

1. 用户 A 请求到达。主线程执行路由代码，发起数据库查询，随后等待 3 秒。
2. 数据库查询完成后，才处理用户 B 的请求。主线程发起文件读取，随后等待 2 秒。
3. 文件读取完成后，才处理用户 C 的请求。主线程执行代码，返回结果。

这样确实效率很低。但 Node.js 并不是这样工作的。

### 5.3 Node.js 的实际执行过程

关键在于：等待 I/O 时，不需要一直占用 JavaScript 主线程。

执行过程大致如下：

1. 用户 A 请求到达。主线程执行路由代码，发起数据库查询，随后等待 I/O。
2. 用户 B 请求到达。主线程执行路由代码，发起文件读取，随后等待 I/O。
3. 用户 C 请求到达。主线程直接执行代码，返回 Hello，快速完成。
4. 用户 B 文件读取完成。主线程恢复执行后续代码，返回文件内容。
5. 用户 A 数据库查询完成。主线程恢复执行后续代码，返回查询结果。

因此，虽然只有一个 JavaScript 主线程，多个请求仍然可以同时处于处理中。



## 线程

线程（Thread）是 CPU 调度和执行代码的最小单位。

操作系统会创建一个进程（Process）。进程里面可以有一个或多个线程（Thread）。
![[Pasted image 20261118113820.png]]

### 线程与CPU

假设你的电脑有一个 4 核 CPU：

- 一个 CPU 核心在某一时刻可以执行一个线程的指令流。
    
- 四个核心可以同时执行四个线程。
    
- 如果有 100 个线程，操作系统会调度它们，让它们轮流使用 CPU。

> [!warn]
> 线程数量不等于 CPU 核心数量。

> 默认启动一个 Node.js 应用，**JS 逻辑只跑在 1 个核心上，但底层的异步 I/O 可能会用到多个核心**。而到了线上生产环境，通常配合 PM2 或容器化多实例部署，就能把多核 CPU 全部利用起来了。
