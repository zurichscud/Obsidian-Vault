## 2. 一个进程有多个线程时，内存怎么分配？

假设一个进程有三个线程：

- 线程 A
- 线程 B
- 线程 C

它们共享进程的堆内存、代码区等资源，但是每个线程拥有自己的线程栈。

![[Pasted image 20261118142625.png]]

### 2.1 堆内存与线程栈

这里有两个重要概念：

- **堆内存（Heap）**：同一个进程内的线程可以访问共享堆内存。
- **线程栈（Stack）**：每个线程有自己的栈，保存函数调用、局部变量等执行信息。

### 2.2 为什么线程需要独立的栈

两个线程的栈相互独立，因此不会直接覆盖对方的局部变量。

## 3. 为什么多个线程共享内存

因为**多个线程有时候需要操作同一份数据**，所以才会出现共享变量。

共享变量的本质是：多个执行线程需要访问同一份数据，因此程序通过共享内存等方式，让它们能够访问同一个数据位置。

### 3.1 为什么需要共享变量

假设你开发一个银行系统，账户余额是 1000 元。有两个线程：

- 线程 A：处理取款 100 元。
- 线程 B：处理存款 200 元。

它们都需要操作同一个账户余额。

![[Pasted image 20261118144449.png]]

如果每个线程都有自己独立的余额变量，就无法直接保证它们操作的是同一个账户余额。所以需要共享数据。

### 3.2 共享变量是怎么产生的

在支持共享内存的多线程语言中，例如 Java：

```
public class Account {
    public int balance = 1000;
}
```

创建一个账户对象：

```
Account account = new Account();
```

然后把同一个对象传给两个线程：

```java
Thread threadA = new Thread(() -> {
    account.balance -= 100;
});

Thread threadB = new Thread(() -> {
    account.balance += 200;
});

threadA.start();
threadB.start();
```

这里的关键是 `account`：两个线程拿到的是同一个对象的引用，因此访问的是同一份 `balance` 数据。

## 4. 线程安全

**线程安全（Thread Safety）** 指的是：当多个线程同时访问同一份数据时，程序仍然能够保证结果正确，不会因为线程之间的执行顺序不同而出现错误。

理解线程安全，需要先理解一个问题：多个线程同时修改同一个变量会发生什么？

### 4.1 什么是线程不安全？

假设有一个共享变量：

```
int count = 0;
```

现在有两个线程，都执行：

```
count++;
```

我们期望最终结果是：

```
count = 2
```

但是，可能出现问题。因为 `count++` 实际上可以拆分成三个步骤：

1. 读取 count。
2. count 加 1。
3. 将结果写回 count。

假设两个线程这样执行：

![[Pasted image 20261118144808.png]]

这就是典型的线程安全问题，称为**竞态条件（Race Condition）**：两个线程都读取了旧值 0，导致其中一次更新丢失。

### 4.2 如何保证线程安全

常见有三种方式。

#### 加锁（Lock）

让同一时刻只有一个线程能够执行关键代码。

```java
public synchronized void increment() {
    count++;
}
```

执行过程：

```
线程 A 获取锁
    ↓
执行 count++
    ↓
释放锁
    ↓
线程 B 获取锁
    ↓
执行 count++
    ↓
释放锁
```

这样就不会出现两个线程同时修改的问题。

#### 原子操作（Atomic）

使用原子类：

```java
AtomicInteger count = new AtomicInteger(0);

count.incrementAndGet();
```

`incrementAndGet()` 保证递增操作具有原子性。


## 5. 为什么 JavaScript 通常不需要考虑这个问题？

普通 Node.js 主线程执行 JavaScript 时，同一时刻只有一个 JavaScript 执行流程。即使有多个 HTTP 请求调用 `increment()`，这些 JavaScript 回调也由主线程依次执行，不会像传统多线程那样同时执行这段同步代码。
