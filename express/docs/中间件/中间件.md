Express 中间件（Middleware）本质上是一个**能够访问请求对象（`req`）、响应对象（`res`）以及应用程序请求-响应周期中下一个中间件函数（通常命名为 `next`）的函数**。

## 1. 中间件函数的签名

一个中间件函数的基本形式如下：

```js
function middleware(req, res, next) {
  // 处理逻辑
  next();
}
```

- `req`：请求对象，包含请求的 URL、方法、头、查询参数、请求体等信息。
- `res`：响应对象，用于向客户端发送响应。
- `next`：函数，调用它会把控制权交给下一个中间件或路由处理函数。

中间件可以做四件事：执行任意代码、修改 `req`/`res` 对象、结束请求-响应周期、调用 `next()` 把控制权传递下去。

## 2. next() 的作用与控制流

`next()` 是中间件链的"接力棒"。理解它的行为是掌握中间件的关键。

### 2.1 调用 next() 交棒

```js
app.use((req, res, next) => {
  console.log('A');
  next(); // 交给下一个中间件
});

app.use((req, res, next) => {
  console.log('B');
  res.send('done');
});
```

访问任意路径会依次打印 `A`、`B`。

### 2.2 不调用 next() 则请求挂起

如果中间件既不调用 `next()`，也不发送响应，请求会一直挂起直到客户端超时：

```js
app.use((req, res, next) => {
  console.log('拦截，但既不 next 也不响应');
  // 请求挂起
});
```

### 2.3 next(err) 跳转到错误处理中间件

传入错误参数会跳过后续普通中间件，直接进入错误处理中间件：

```js
app.get('/users/:id', (req, res, next) => {
  if (isNaN(req.params.id)) {
    return next(new Error('id 必须是数字'));
  }
  next();
});
```

### 2.4 next('route') 跳过当前路由的剩余处理函数

在路由处理函数链中，`next('route')` 会跳过当前路由剩余的处理函数，匹配下一条路由：

```js
function checkId(req, res, next) {
  if (isNaN(req.params.id)) return next('route');
  next();
}

app.get('/users/:id', checkId, (req, res) => {
  res.send('正常用户');
});

app.get('/users/:id', (req, res) => {
  res.send('兜底处理');
});
```

### 2.5 next() 之后的代码仍会执行

`next()` 不会终止当前函数，调用后函数继续执行。因此发送响应后应 `return`：

```js
app.use((req, res, next) => {
  if (!req.headers.authorization) {
    res.status(401).send('未授权');
    // 缺少 return：下面的 next() 仍会执行，导致重复处理
  }
  next();
});
```

## 3. 中间件的分类

### 3.1 应用级中间件

通过 `app.use()` / `app.METHOD()` 挂载，作用于整个应用或指定路径前缀：

```js
app.use((req, res, next) => { /* 全局日志 */ next(); });
app.use('/api', express.json()); // 仅 /api 前缀生效
```

### 3.2 路由级中间件

挂载到 `express.Router()` 实例，作用于该 Router 下的所有路由：

```js
const router = express.Router();
router.use(authRequired);
router.get('/profile', getProfile);
app.use('/users', router);
```

### 3.3 错误处理中间件

签名为 `(err, req, res, next)`，四个参数，Express 据此识别为错误处理器。详见 `express/中间件/错误处理中间件.md`。

### 3.4 内置中间件

Express 内置的中间件，无需安装第三方包，包括 `express.json()`、`express.urlencoded()`、`express.static()`、`express.raw()` / `express.text()`。详见 `express/中间件/内置中间件.md`。

### 3.5 第三方中间件

通过 npm 安装，常见如 `cors`、`helmet`、`morgan`、`cookie-parser`、`multer`、`compression` 等。详见 `express/中间件/第三方中间件.md`。

## 4. 执行顺序

Express 按**注册顺序**依次执行中间件，匹配到第一条就进入，不再回溯。因此顺序决定行为。

```js
app.use(express.static('public'));   // 1. 静态文件优先
app.use(express.json());             // 2. 解析请求体
app.use(requestLogger);             // 3. 日志
app.use('/api', apiRouter);         // 4. 路由
app.use(notFoundHandler);           // 5. 404 兜底（最后）
app.use(errorHandler);              // 6. 错误处理（最最后）
```

要点：
- `app.use('/api', ...)` 按前缀匹配：命中 `/api` 与 `/api/users`，不命中 `/`。
- 静态资源中间件应放在路由之前，避免请求被路由拦截。
- Body 解析中间件必须在读取 `req.body` 的路由之前注册。
- 错误处理中间件必须注册在所有路由与普通中间件之后。

## 5. 常见坑

1. **忘记调用 `next()`**：请求挂起，客户端最终超时。
2. **`next()` 后继续执行**：导致重复发送响应，抛出 `ERR_HTTP_HEADERS_SENT`。
3. **错误中间件参数数量不对**：必须是 4 个参数，少一个就被当作普通中间件。
4. **中间件注册顺序错误**：Body 解析放在路由之后、静态资源放在路由之后都会导致失效。
5. **异步错误未转发**：Express 4 中 async 抛错不会自动进入错误中间件，需 `try/catch` + `next(err)`。
6. **在错误中间件里重复响应**：发送前先检查 `res.headersSent`。

## 6. 最佳实践

1. 按"安全 → 解析 → 日志 → 路由 → 404 → 错误处理"的顺序注册中间件。
2. 一个中间件只做一件事，便于复用与测试。
3. 自定义中间件放 `middlewares/` 目录，通过 `module.exports` 导出。
4. 认证、校验等横切逻辑放在中间件，控制器只处理请求/响应。
5. 异步中间件统一 `try/catch` + `next(err)`（Express 4）；Express 5 项目可依赖自动捕获。
