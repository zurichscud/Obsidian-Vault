在 Express 中，`router.get(path, fn1, fn2, ...)` 本质上是构建了一个**串行的中间件执行链（Middleware Chain）**。

以下代码演示一个由两个处理函数组成的中间件链：

```js
router.get('/:id', validate({ params: categoryIdParamsSchema }), getCategory);
```

## 1. 基本语法

Express 的路由方法（`get`、`post` 等）签名支持接收多个函数或函数数组。

以下代码给出同一路由的两种写法：离散参数形式与数组形式：

```js
// 形式 1：离散参数（你的代码写法）
router.get('/:id', validate({ params: categoryIdParamsSchema }), getCategory);

// 形式 2：数组形式
router.get('/:id', [validate({ params: categoryIdParamsSchema }), getCategory]);
```

Express 底层会使用 `Array.flat()` 将传入的所有处理函数展开成一个扁平的队列 `[fn1, fn2]`，并为它们绑定相同的路径上下文。

## 2. 执行机制

中间件链的驱动完全依赖 `next()` 函数。中间件链的执行顺序遵循**严格的从左到右、层层嵌套的队列机制（FIFO，先进先出）**。

- **正常推进（`next()`）**：`validate` 执行完毕后调用无参的 `next()`，Express 内部指针由当前中间件指向队列中的下一个函数，即 `getCategory`。
- **短路跳出（`next(err)`）**：如果入参不合法，`validate` 调用 `next(new Error(...))`。Express 侦测到 `next` 携带了参数，会**立刻跳过链条中后续所有的普通中间件**（`getCategory` 根本不会被调用），直接跳转到具有 4 个参数的全局错误处理中间件 `(err, req, res, next)`。
- **直接响应截断（`res.send` / `res.json`）**：如果某个中间件直接调用了 `res.status(400).json(...)` 且没有调用 `next()`，链条直接终止，后续中间件同样不会被触发。

> [!warning] 注意
> 如果前面的中间件既**没有调用 `next()`**，又**没有调用结束响应的方法**（如 `res.send()`、`res.json()`、`res.end()`），Express 的执行链条就会**彻底卡死在该节点**。

## 3. 上下文共享

中间件链上的每个函数接收到的都是**同一个 `req` 和 `res` 对象引用**。链条前面的中间件对 `req` 的修改，后面的中间件可以直接感知：

```js
// 节点 1：校验并清洗数据
const validate = (schema) => (req, res, next) => {
  const result = schema.safeParse(req.params);
  if (!result.success) {
    return next(result.error);
  }
  
  // 核心：直接改写 req.params，把原本的 string "123" 替换为清洗后的 number 123
  req.params = result.data; 
  next();
};

// 节点 2：下游控制器
const getCategory = (req, res) => {
  // 直接拿到上游清洗过的数据，无需重复转换
  console.log(typeof req.params.id); // 'number'
  res.json({ id: req.params.id });
};
```

## 4. 任意扩展能力

中间件链支持无限追加节点，常见模式是按顺序排列：**权限认证 -> 权限校验 -> 参数校验 -> 业务处理**。

以下代码演示按该顺序在单个路由上追加多个节点：

```js
router.get(
  '/:id',
  authenticate,                                    // 1. 验证用户 Token 是否合法
  authorize(['ADMIN', 'OPERATOR']),                // 2. 验证用户角色权限
  validate({ params: categoryIdParamsSchema }),    // 3. 拦截非法入参
  getCategory                                      // 4. 执行业务逻辑
);
```

每个环节只要出现问题（如未登录、权限不足、参数错误），调用 `next(err)` 就会立即截断链条，保障下游 Controller 永远在一个“已验证、已授权、数据合法”的安全环境下执行。
