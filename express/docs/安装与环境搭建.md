在 Express 生态中，最主流且官方推荐的脚手架是 **`express-generator`**。它可以快速搭建一个包含基础目录结构、路由分发、静态资源托管和模板引擎配置的标准工程。

## 1. 快速生成项目

无需全局安装，推荐使用 `npx` 直接运行。下面给出命令格式与示例：

```bash
# 格式：npx express-generator [项目名称] [参数]
# 示例：创建一个名为 my-express-app 的项目，并指定模板引擎（如 ejs、pug，若做纯接口可忽略或使用 --no-view）
npx express-generator my-express-app --no-view
```

> **参数说明：**
>
> - `--no-view`：不生成视图引擎代码（适合纯前后端分离的 RESTful API 开发）。
> - `--view=ejs` / `--view=pug`：指定服务端渲染的模板引擎。
> - `--git`：自动生成 `.gitignore` 文件。

## 2. 安装依赖并启动

进入项目目录后依次安装依赖、启动项目：

```bash
# 1. 进入项目目录
cd my-express-app

# 2. 安装依赖
npm install

# 3. 启动项目
npm start
```

默认会启动在 `http://localhost:3000`。

## 3. 生成的目录结构

一个标准生成的 API 项目目录如下：

```text
my-express-app/
├── bin/
│   └── www             # 服务启动入口（配置端口、创建 HTTP Server、监听错误等）
├── public/             # 静态资源目录（图片、样式、前端脚本）
├── routes/             # 路由模块
│   ├── index.js        # 基础路由
│   └── users.js        # 示例模块路由
├── app.js              # Express 核心应用配置（装载中间件、挂载路由、错误处理）
└── package.json        # 项目配置及脚本
```

**关键文件职责分工：**

- **`bin/www`**：处理底层 Node.js `http.createServer`、端口绑定（`PORT` 环境变量）以及 `listening` / `error` 事件监听。
- **`app.js`**：负责组装 Express 实例，注册内置及第三方中间件（如 `morgan` 日志记录、`express.json()` 解析请求体、`cookieParser` 解析 Cookie 等），并将顶层路径分配给 `routes/` 下的子路由。

## 4. 生产/开发环境改进实践

`express-generator` 生成的代码非常朴素，日常开发中通常会在此基础上做几处增强。

### 4.1 增加热重载支持

默认的 `npm start`（运行 `node ./bin/www`）修改代码后需要手动重启，推荐安装 `nodemon`：

```bash
npm install -D nodemon
```

随后在 `package.json` 的 `scripts` 中增加开发命令：

```json
"scripts": {
  "start": "node ./bin/www",
  "dev": "nodemon ./bin/www"
}
```

> [!warning] 注意
> `node --watch` 是 Node.js 官方内置的文件监听热重启功能，从 Node.js **v18.11.0** 开始实验性引入，并在 **v20 / v22+** 中成为主流开发实践。

现在许多新项目选择弃用 `nodemon`、改用 `node --watch`
### 4.2 分层架构扩展

`routes/` 默认将路由分发和业务逻辑写在一起。项目变大后，通常重构成：

- `routes/`：只负责 URL 路径与 HTTP 动词绑定。
- `controllers/`：接收请求、参数校验、调用业务逻辑并返回响应。
- `services/`：核心业务逻辑处理。
- `models/`：数据库模型（如 Prisma、Sequelize 或 Mongoose 模型）。
