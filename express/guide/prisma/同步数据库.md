## 1. Migrate（push）

**Migrate（数据库迁移）** 指的是**将代码中定义的数据库结构（Prisma Schema）同步并变更到实际数据库**的过程。

>它就像数据库的 Git：通过记录每一次数据表结构的修改，确保开发环境和生产环境的数据库结构保持完全一致，且变更过程可追溯、可重复。

执行迁移：

```sh
pnpm prisma migrate dev --name 迁移名称
```

该命令会依次执行以下步骤：

1. **读取数据库**：连接到 `.env` 中配置的数据库。
2. 检测 Schema 差异（Diff）。
3. **生成 `migration.sql` 迁移文件**：在 `prisma/migrations/` 目录下创建一个带有**时间戳 + 名称**的新文件夹（例如 `20260908120000_add_user_status`），并在其中生成对应的 SQL 变更脚本（`migration.sql`）。
4. **检测一致性**：检查数据库的实际结构是否与 `migrations` 文件夹中的历史记录一致。如果检测到有人手动在数据库中改了表结构（即破坏了迁移链条），Prisma 会提示发生漂移，并询问是否重置数据库。
5. 应用未执行的 SQL 迁移。
6. 更新数据库中的 `_prisma_migrations` 追踪表。
7. 自动触发 `prisma generate`。

不生成任何 SQL 迁移历史，直接强制将 Schema 覆盖应用到数据库：

```sh
pnpm prisma db push
```

## 2. Introspection（pull）

如果需要**将已有数据库的表结构同步并生成到本地代码中的 `schema.prisma` 文件**，在 Prisma 中这个过程叫做 **Introspection（反向工程 / 数据库内省）**。

执行内省：

```sh
pnpm prisma db pull
```

它会执行以下工作：

1. **读取数据库**：连接到 `.env` 中配置的数据库。
2. **分析表结构**：读取所有的表、列、主键、外键索引和数据类型。
3. **更新 Schema**：自动重写或更新本地的 `prisma/schema.prisma` 文件，将数据库表转换成 Prisma 的 `model` 定义。

> [!warning] 注意
> 完成数据库内省后，需要手动重新生成 Prisma Client，这样生成的代码才能反映最新的数据库结构。
