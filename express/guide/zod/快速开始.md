Zod 是一个面向 TypeScript 的数据校验库，可以用一份 Schema 同时完成运行时数据校验和 TypeScript 类型推导。

如果你在开发 Next.js、Express、React 或 Node.js 后端，Zod 都很有用。特别是在开发前后端分离项目时，它可以帮助你校验请求参数、表单数据、环境变量和 API 返回的数据。

## 1. 为什么需要 Zod

先看一个常见的场景：你正在使用 Express 开发用户注册接口。客户端发送：

```json
{
  "username": "zhangsan",
  "age": 18
}
```

你希望满足以下要求：

- `username` 必须是字符串。
- `age` 必须是数字。
- `age` 必须大于 0。

### 1.1 不使用 Zod

你可能需要手动编写校验逻辑：

```javascript
app.post("/register", (req, res) => {
  const { username, age } = req.body;

  if (typeof username !== "string") {
    return res.status(400).json({
      message: "username 必须是字符串",
    });
  }

  if (typeof age !== "number" || age <= 0) {
    return res.status(400).json({
      message: "age 必须是大于 0 的数字",
    });
  }

  // 执行注册逻辑
  res.json({ message: "注册成功" });
});
```

这种方式没有问题，但随着业务复杂度增加，校验代码会越来越多。例如，用户注册还需要校验邮箱格式、密码长度、手机号格式等。

### 1.2 使用 Zod

首先定义校验规则：

```javascript
import { z } from "zod";

const RegisterSchema = z.object({
  username: z.string(),
  age: z.number().positive(),
});
```

然后校验数据：

```javascript
const data = RegisterSchema.parse({
  username: "zhangsan",
  age: 18,
});
```

校验成功后，`data` 就是经过校验的数据。

如果传入错误的数据：

```javascript
RegisterSchema.parse({
  username: 123,
  age: -1,
});
```

Zod 会抛出校验错误，指出哪些字段不符合要求。

这里的关键是：

**你只需要定义一次校验规则，就可以反复使用它，而不必每次手动编写 `if` 判断。**

## 2. 核心概念：Schema 是什么

学习 Zod，首先要理解 `Schema`。

Schema 可以理解为：**一份描述数据应该具备什么结构、满足什么条件的规则定义。**

例如：

```javascript
import { z } from "zod";

const UserSchema = z.object({
  name: z.string(),
  age: z.number(),
  email: z.email(),
});
```

这段代码定义了一个用户对象的 Schema。它要求数据满足以下条件：

| 字段      | 校验规则     |
| ------- | -------- |
| `name`  | 必须是字符串   |
| `age`   | 必须是数字    |
| `email` | 必须符合邮箱格式 |

注意，这段代码只是定义规则，**并没有校验任何实际数据**。只有调用相关方法，才会真正执行校验。

例如：

```javascript
UserSchema.parse({
  name: "张三",
  age: 18,
  email: "zhangsan@example.com",
});
```

校验通过，返回数据。如果邮箱格式错误，就会产生校验错误。
