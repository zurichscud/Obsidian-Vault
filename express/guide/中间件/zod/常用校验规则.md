Zod 提供了丰富的内置校验规则。

## 1. 字符串校验

### 1.1 常见格式校验

这类方法专门用于校验常见规范格式，绝大多数都支持传入自定义错误信息。下面的示例覆盖邮箱、URL、UUID/CUID、正则以及日期时间与网络格式：

```javascript
import { z } from "zod";

// 1. 邮箱校验 (email)
const emailSchema = z.string().email("请输入有效的邮箱地址");

// 2. URL 链接校验
const urlSchema = z.string().url("链接必须以 http/https 开头");

// 3. UUID / CUID 校验 (数据库主键常用)
const uuidSchema = z.string().uuid("无效的 UUID 格式");
const cuidSchema = z.string().cuid();   // CUID v1
const cuid2Schema = z.string().cuid2(); // CUID v2
const ulidSchema = z.string().ulid();   // ULID

// 4. 正则表达式校验 (regex)
const phoneSchema = z.string().regex(/^1[3-9]\d{9}$/, "手机号格式不正确");

// 5. 日期时间与网络格式
const isoDateSchema = z.string().datetime(); // ISO 8601 格式，如 "2026-10-29T13:38:00Z"
const ipSchema = z.string().ip({ version: "v4" }); // 支持 "v4" | "v6"
const base64Schema = z.string().base64();
const jwtSchema = z.string().jwt();
```

### 1.2 长度与前后缀校验

下面的示例针对长度、前后缀与固定长度做校验：

```javascript
const usernameSchema = z
  .string()
  .min(3, "用户名至少 3 个字符")
  .max(20, "用户名最多 20 个字符")
  .startsWith("user_", "用户名必须以 user_ 开头")
  .endsWith("_test"); // 还可以用 .includes("abc")

// 严格固定长度
const verifyCodeSchema = z.string().length(6, "验证码必须为 6 位数字");
```

## 2. 数字校验

常用的数字校验方法如下：

```javascript
z.number().positive();  // 大于 0
z.number().negative();  // 小于 0
z.number().int();       // 整数
z.number().min(1);      // 大于或等于 1
z.number().max(100);    // 小于或等于 100
```

注意：`z.number()` 默认不接受字符串形式的数字。

如果数字范围 **不包含等于**，使用 `.gt()` 和 `.lt()`：

```js
const NumberSchema = z.coerce.number()
  .gt(0)
  .lt(10);
```

这表示：

- `.gt(0)`：大于 0，不包含 0。
- `.lt(10)`：小于 10，不包含 10。

## 3. 枚举值校验

例如，订单状态只能是 `pending`、`paid` 或 `cancelled`：

```javascript
const OrderStatusSchema = z.enum([
  "pending",
  "paid",
  "cancelled",
]);
```

下面的示例分别校验合法与非法状态值：

```javascript
OrderStatusSchema.parse("paid"); // 成功

OrderStatusSchema.parse("unknown"); // 失败
```

## 4. 对象、数组与嵌套结构

真实项目中的数据往往不是简单的字符串或数字，而是复杂对象。Zod 可以组合多个 Schema 来描述它们。

### 4.1 对象校验

下面的示例用 `z.object()` 描述一个包含 `name` 和 `age` 的用户对象：

```javascript
const UserSchema = z.object({
  name: z.string(),
  age: z.number(),
});
```

### 4.2 数组校验

数组还可以进一步限制元素数量：

```javascript
const UsersSchema = z.array(
  z.object({
    name: z.string(),
    age: z.number(),
  })
).min(1).max(100);
```

### 4.3 嵌套对象

例如，一个订单包含用户信息和商品列表：

```javascript
const OrderSchema = z.object({
  orderId: z.string(),

  user: z.object({
    id: z.number(),
    name: z.string(),
  }),

  items: z.array(
    z.object({
      productId: z.number(),
      quantity: z.number().int().positive(),
    })
  ),
});
```

## 5. optional、nullable 与 default

假设用户资料中的 `nickname` 不是必填字段。

### 5.1 默认情况

字段值为 `undefined` 时，校验会直接失败。下面的示例中，`name` 传入 `undefined`：

```js
const schema = z.object({
  name: z.string()
})

schema.parse({
  name: undefined //通常是前端未传
})
// ZodError: Invalid input
```

### 5.2 optional()：允许字段缺失

任何其他类型（包括 `null`、空字符串 `""`、`0`、`false`）都**不会**被视为 `undefined`，仍然会触发类型错误。

下面的示例用 `.optional()` 将 `nickname` 设为可选字段：

```javascript
import { z } from 'zod';

const Schema = z.object({
  status: z.string().optional(),
});

Schema.parse({ status: undefined }); // ✅ 通过 -> { status: undefined }
Schema.parse({});                   // ✅ 通过 -> {}
Schema.parse({ status: "active" }); // ✅ 通过 -> { status: "active" }

Schema.parse({ status: null });     // ❌ 报错: Expected string, received null
Schema.parse({ status: "" });       // ✅ 通过（"" 是合法的 string，但不是 undefined）
```



### 5.3 nullable()：允许值为 null

下面的示例用 `.nullable()` 允许 `nickname` 取 `null`：

```javascript
const UserSchema = z.object({
  nickname: z.string().nullable(),
});
```

允许：

- `{ nickname: "小张" }`
- `{ nickname: null }`

### 5.4 default()：缺失时使用默认值

下面的示例为 `role` 设置默认值 `"user"`：

```javascript
const UserSchema = z.object({
  role: z.string().default("user"),
});
```

解析空对象：

```javascript
const result = UserSchema.parse({});
```

解析结果如下：

```javascript
{
  role: "user"
}
```

### 5.5 空串

对于空串，zod没有提供专门的方法判断。可以将其转为`undefined`再处理

```js
const emptyToUndefined = (value) =>

value === "" || value === null ? undefined : value;
```

## 6. refine：自定义校验规则

Zod 的内置规则可以处理大部分常见情况，但业务逻辑往往还有特殊要求。

下面的示例在密码校验中依次要求包含小写字母、大写字母和特殊字符：

```javascript
import { z } from "zod";

const PasswordSchema = z
  .string()
  .min(9, "密码至少需要 9 位")
  .refine((value) => /[a-z]/.test(value), {
    error: "密码必须包含小写字母",
  })
  .refine((value) => /[A-Z]/.test(value), {
    error: "密码必须包含大写字母",
  })
  .refine((value) => /[^a-zA-Z0-9]/.test(value), {
    error: "密码必须包含特殊字符",
  });
```

校验结果如下：

```javascript
PasswordSchema.safeParse("Abcdefg!1"); // 成功
PasswordSchema.safeParse("abcdefg!1"); // 缺少大写字母
PasswordSchema.safeParse("ABCDEFG!1"); // 缺少小写字母
PasswordSchema.safeParse("Abcdefghi"); // 缺少特殊字符
PasswordSchema.safeParse("Ab!1");      // 长度不足
```

## 7. 自定义错误提示

在 Zod 4 中，可以在 Schema API 中自定义错误提示。

### 7.1 直接传入字符串

在规则中直接传入错误提示字符串：

```js
z.string().max(20, '最多不能超过 20 个字符')
```

### 7.2 传入配置对象

在规则中传入包含 `error` 字段的配置对象：

```js
z.string()
  .min(3, { error: '至少 3 个字符' })
  .max(20, { error: '最多 20 个字符' })
  .email({ error: '邮箱格式不正确' })
  .url({ error: 'URL 格式不正确' })
  .regex(/^[a-z]+$/, { error: '只能包含小写字母' })
```
