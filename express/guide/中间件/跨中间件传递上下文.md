在 Express 中，`req.user` 和 `res.locals` 虽然都可以用来跨中间件传递数据，但两者的**语义角色**和**生命周期关注点**截然不同：

- **`req`（Request）关注的是「调用方是谁、带着什么输入来」**：`req.user` 是当前发起请求的**身份上下文（Identity Context）**。
- **`res`（Response）关注的是「本次响应准备产出什么、响应管线共享什么」**：`res.locals` 是当前请求-响应生命周期内的**响应级临时共享存储区（Response Context / View Context）**。

## 1. 挂载在 `req.user` 的信息

`req.user` 属于约定俗成的规范（如 Passport.js、自定义 JWT Auth 中间件），用来表示**经过认证（Authentication）后的当前访问主体**。

### 1.1 适合挂载的内容

- **用户核心身份标识**：`id` / `userId`、`username`、`tenantId`（多租户 ID）。
- **安全与权限凭证**：用户角色（`roles: ['admin', 'editor']`）、权限代码集（`permissions: ['user:read', 'user:write']`）。
- **令牌元数据（轻量级）**：JWT 中的 `sessionId`、`tokenExp`。

### 1.2 示例：JWT 鉴权中间件挂载身份信息

以下代码演示 JWT 鉴权中间件在解析令牌后，把身份元信息挂载到 `req.user`，供后续路由守卫、RBAC 中间件、Controller 消费：

```ts
// 典型场景：JWT 鉴权中间件解析后挂载
const authenticateToken = (req: Request, res: Response, next: NextFunction) => {
  const token = req.headers.authorization?.split(' ')[1];
  const payload = verifyJwt(token);

  // 挂载身份元信息，供后续路由守卫、RBAC 中间件、Controller 消费
  req.user = {
    id: payload.userId,
    username: payload.sub,
    roles: payload.roles,
    tenantId: payload.tenantId
  };
  next();
};
```

### 1.3 边界原则

> 不要将整张用户表的大对象（如详细 profile、加密密码、大段地址列表）挂上去，仅存放鉴权与审计所需的**轻量凭据**即可。

## 2. 挂载在 `res.locals` 的信息

`res.locals` 是 Express 官方原生提供的对象（生命周期仅限当次请求响应）

### 2.1 适合挂载的内容

- **全链路追踪与可观测性数据**：`requestId` / `traceId`、请求开始时间戳 `startTime`。
- **业务执行的中间/派生状态**：例如多层中间件计算得到的 `targetResource`（如根据 URL 预先查出的待操作文章对象）、格式化后的分页参数。
- **统一错误处理上下文**：在业务逻辑出错时附带的中间上下文数据。

### 2.2 示例：链路追踪与前置资源装载

以下代码包含两个典型场景：链路追踪中间件写入 `requestId` 与 `startTime`；前置资源装载中间件查出 `project` 后暂存到 `res.locals`，避免在 Controller 和鉴权中间件里查两次 DB：

```ts
// 典型场景 1：链路追踪中间件
app.use((req, res, next) => {
  res.locals.requestId = req.headers['x-request-id'] || crypto.randomUUID();
  res.locals.startTime = Date.now();
  next();
});

// 典型场景 2：前置资源装载中间件（避免在 Controller 和鉴权中间件里查两次 DB）
const loadProject = async (req: Request, res: Response, next: NextFunction) => {
  const project = await prisma.project.findUnique({ where: { id: req.params.projectId } });
  if (!project) return res.status(404).json({ message: 'Project not found' });

  // 暂存供后续的 RBAC 校验或 Controller 使用
  res.locals.project = project;
  next();
};
```

### 2.3 对象的本质与可见范围

`res.locals` 本质上只是 Express 在**服务端内存**中为当前请求分配的一个临时普通 JavaScript 对象。除非你**显式**把里面的字段塞进响应体。
