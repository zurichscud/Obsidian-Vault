## 1. 上传流程

### 1.1 客户端向后端申请上传权限

用户选择一张图片：

```
const file = event.target.files[0];
```

例如，选中的文件信息如下：

```
文件名：avatar.png
文件大小：2 MB
文件类型：image/png
```

客户端向后端发送文件的元数据：

```
POST /api/upload/authorize
Content-Type: application/json
Authorization: Bearer 用户登录令牌

{
  "fileName": "avatar.png",
  "contentType": "image/png",
  "fileSize": 2097152
}
```

### 1.2 后端验证并生成上传授权

后端需要检查：

1. 用户是否登录。
2. 用户是否有上传权限。
3. 文件大小是否符合要求。
4. 文件类型是否在允许范围内。

此外，后端还需要生成一个由后端控制的对象存储路径。例如，后端生成：

```
uploads/2026/10/27/随机UUID.png
```

然后根据选定的授权方案生成预签名 URL 或 STS 临时凭证。

后端返回的数据可以设计成：

```
{
  "objectKey": "uploads/2026/10/27/abc123.png",
  "uploadUrl": "https://example-bucket.oss-cn-hangzhou.aliyuncs.com/uploads/2026/10/27/abc123.png?签名参数",
  "method": "PUT",
  "expiresIn": 300
}
```

这是一个示意结构，实际的签名参数由 OSS SDK 生成。

其中：

| 字段 | 作用 |
|---|---|
| `objectKey` | 文件在 OSS 中的对象名称 |
| `uploadUrl` | 客户端执行 PUT 上传时使用的授权 URL |
| `method` | 上传 HTTP 方法 |
| `expiresIn` | 授权有效期，示例为 300 秒 |

**重要：** 预签名 URL 不是普通的文件地址，它是一个携带临时授权信息的 URL。

### 1.3 浏览器直接上传文件

客户端拿到 `uploadUrl` 后，直接向 OSS 发送文件：

```
async function uploadFile(file, uploadUrl) {
  const response = await fetch(uploadUrl, {
    method: "PUT",
    headers: {
      "Content-Type": file.type,
    },
    body: file,
  });

  if (!response.ok) {
    throw new Error(`上传失败：${response.status}`);
  }

  return true;
}
```

这里有几个关键点。

**1. 请求地址是 OSS，不是你的后端。**

```
fetch(uploadUrl, ...)
```

由于 `uploadUrl` 指向 OSS，因此文件数据直接发送给 OSS。

**2. `body: file` 传输的是文件内容。**

浏览器会读取用户选择的 `File` 对象，并将其作为请求体发送。对于这种 PUT 上传方式，不需要先把整个文件转换成 Base64 字符串。

**3. 请求头必须与签名约束一致。**

如果预签名 URL 对 `Content-Type` 等请求参数作了约束，客户端必须按照签名时的要求发送请求，否则可能收到 `403` 等错误。

**4. OSS 必须配置正确的 CORS 规则。**

如果网页与 OSS 不属于相同的源，浏览器的跨域机制就可能影响上传。你需要根据实际请求配置 OSS 的跨域来源、允许的方法和请求头。相关要求可参考阿里云的 [OSS Browser.js SDK 文档](https://www.alibabacloud.com/help/zh/oss/developer-reference/initialization?utm_source=chatgpt.com)。

### 1.4 客户端通知后端上传结果

文件上传成功后，客户端可以通知后端：

```
POST /api/upload/complete
Content-Type: application/json

{
  "objectKey": "uploads/2026/10/27/abc123.png"
}
```

后端收到请求后，不能仅凭客户端说上传成功就认定文件已经存在。

更稳妥的做法是：**后端通过 OSS 服务端接口检查对象是否存在，并根据业务要求核对文件大小、类型等信息。**

验证通过后，再把文件记录关联到用户的头像或其他业务数据。

也可以采用 OSS 上传回调等机制，让后端获知上传结果。

## 2. 客户端直传实现

- **预签名 URL**：后端直接生成一个带有签名的请求地址，客户端拿着这个地址上传文件。
- **STS 临时凭证**：后端向客户端提供一组有时效的临时访问凭证，客户端使用这些凭证，通过 OSS SDK 访问 OSS。

| 对比项 | 预签名 URL | STS 临时凭证 | POST 签名 |
|---|---|---|---|
| 授权方式 | signatureUrl | assumeRole | calculatePostSignature |
| 前端需要安装 `ali-oss` | ❌ | ✅ | ❌ |
| 上传方式 | `PUT` | SDK | `POST` |
| 适用场景 | 普通文件上传 | 复杂上传、分片上传 | 需要 POST 表单上传 |
| **推荐程度** | 常用 | 常用 | 特定场景使用 |

### 2.1 方式 A：预签名 URL（PutObject）

可以使用 OSS SDK 生成一个预签名 URL。例如：

```
https://my-bucket.oss-cn-hangzhou.aliyuncs.com/uploads/avatar.png
    ?签名参数
```

这个 URL 包含了用于验证授权的签名信息。你可以把它理解为一张**限定了访问目标和有效期的临时通行证**。

#### 服务端

服务端调用 `signatureUrl` 生成预签名 URL：

```js
const uploadUrl = client.signatureUrl("uploads/avatar.png", {
  method: "PUT",
  expires: 300,
  "Content-Type": "image/png",
});
```

#### 客户端

客户端不需要知道后端的 AccessKey Secret，只需要拿到这个 URL，就可以按照约定的方式上传文件。

```
await fetch(uploadUrl, {
  method: "PUT",
  headers: {
    "Content-Type": file.type,
  },
  body: file,
});
```

### 2.2 方式 B：PostObject

#### 服务端

服务端提供签名接口，计算 policy 与 signature：

```js
const express = require('express');
const OSS = require('ali-oss');
const path = require('path');
const crypto = require('crypto');


// 允许上传的 MIME 白名单
const ALLOWED_MIME_TYPES = new Set(['image/jpeg', 'image/png', 'image/webp', 'application/pdf']);

app.post('/api/oss/post-signature', (req, res) => {
  try {
    const { filename, mimeType } = req.body;

    if (!mimeType || !ALLOWED_MIME_TYPES.has(mimeType)) {
      return res.status(400).json({ code: 400, message: '不支持的文件类型' });
    }

    const ext = path.extname(filename || '').toLowerCase();
    const datePrefix = new Date().toISOString().slice(0, 10).replace(/-/g, '');
    const objectKey = `uploads/${datePrefix}/${Date.now()}-${crypto.randomBytes(4).toString('hex')}${ext}`;

    // 1. 设置 10 分钟后过期
    const expiration = new Date(Date.now() + 10 * 60 * 1000).toISOString();

    // 2. 构造策略对象
    const policy = {
      expiration,
      conditions: [
        { bucket: process.env.OSS_BUCKET },
        // 精准匹配，防止前端覆盖其他路径
        ['eq', '$key', objectKey],
        // 核心安全：限制文件大小为 1B ~ 10MB
        ['content-length-range', 1, 10 * 1024 * 1024],
        // 核心安全：强校验 Content-Type
        ['eq', '$Content-Type', mimeType]
      ]
    };

    // 3. 一键计算 policy base64 和 signature
    const signatureData = client.calculatePostSignature(policy);

    // 构造直传地址：https://<bucket>.<region>.aliyuncs.com
    const host = `https://${process.env.OSS_BUCKET}.${process.env.OSS_REGION}.aliyuncs.com`;

    res.json({
      code: 200,
      data: {
        host,
        key: objectKey,
        contentType: mimeType,
        policy: signatureData.policy,
        signature: signatureData.Signature,
        ossAccessKeyId: client.options.accessKeyId
      }
    });
  } catch (err) {
    console.error('签名计算失败:', err);
    res.status(500).json({ code: 500, message: '获取签名失败' });
  }
});
```

`calculatePostSignature` 返回的对象结构如下：

```js
{
  policy: 'eyBleHBpcmF0aW9uIjogIjIwMjYtMTAtMjdUMTE6...', // 已经 Base64 编码后的 policy 字符串
  Signature: 'v5sK2X6L7qj...'                            // 计算出的 HMAC-SHA1 签名
}
```

该对象中的键名存在大小写差异：

- 键名是 **首字母大写** 的 `Signature`。
- 前端组装 `FormData` 向 OSS 提交时，字段名必须严格区分大小写（`OSSAccessKeyId`、`policy`、`Signature`、`key`、`file`），否则 OSS 会报错。

#### 客户端

POST 上传通常使用 `multipart/form-data`，并携带相关表单字段和文件：

```js
const formData = new FormData();

formData.append("key", data.key);
formData.append("policy", data.policy);
formData.append("OSSAccessKeyId", data.ossAccessKeyId);
formData.append("Signature", data.Signature);
formData.append("file", file);

await fetch(data.host, {
  method: "POST",
  body: formData,
});
```

### 2.3 方式 C：STS

STS 是 Security Token Service，即安全令牌服务。

它的核心思想与预签名 URL 不同：

**后端不是直接给客户端一个可执行的上传地址，而是向客户端发放一组有时效的临时访问凭证。**

#### 服务端

后端调用 `sts.assumeRole` 获取临时凭证：

```js
// 获取临时凭证
app.post("/api/oss/sts", async (req, res) => {
  try {
    const result = await sts.assumeRole(
      process.env.OSS_ROLE_ARN,//OSS_ROLE_ARN:指定要扮演的 RAM 角色
      "",       // 暂时不传额外的会话策略
      "1800",   // 凭证有效期：1800 秒
      "oss-upload-session"
    );

    res.json({
      accessKeyId: result.credentials.AccessKeyId,
      accessKeySecret: result.credentials.AccessKeySecret,
      securityToken: result.credentials.SecurityToken,
      expiration: result.credentials.Expiration,
    });
  } catch (error) {
    console.error("获取 STS 凭证失败：", error);

    res.status(500).json({
      message: "获取 STS 凭证失败",
    });
  }
});
```

返回给客户端的凭证结构如下：

```json
{
  "accessKeyId": "临时AccessKeyId",
  "accessKeySecret": "临时AccessKeySecret",
  "securityToken": "临时安全令牌"
}
```

| 字段 | 作用 |
|---|---|
| `accessKeyId` | 标识临时访问凭证 |
| `accessKeySecret` | 用于计算请求签名 |
| `securityToken` | 携带临时安全令牌，用于验证临时授权身份 |

#### 客户端

客户端使用这些凭证，通过 OSS SDK 发起请求：

```js
import OSS from "ali-oss";

async function uploadFile(file) {
  // 1. 向 Express 后端获取 STS 临时凭证
  const response = await fetch("/api/oss/sts", {
    method: "POST",
    credentials: "include",
  });

  if (!response.ok) {
    throw new Error("获取 STS 凭证失败");
  }

  const sts = await response.json();

  // 2. 使用临时凭证创建 OSS 客户端
  const client = new OSS({
    region: "oss-cn-hangzhou", // 替换为你的 OSS 地域
    bucket: "你的Bucket名称",

    accessKeyId: sts.accessKeyId,
    accessKeySecret: sts.accessKeySecret,
    stsToken: sts.securityToken,

    authorizationV4: true,
  });

  // 3. 生成 OSS 对象名称
  const objectKey = `uploads/${crypto.randomUUID()}-${file.name}`;

  // 4. 直接上传到 OSS
  const result = await client.put(objectKey, file);

  console.log("上传成功", result);

  return {
    objectKey,
    url: result.url,
  };
}
```
