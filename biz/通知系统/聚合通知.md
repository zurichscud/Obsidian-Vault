下面以「多人点赞同一篇帖子」为例，完整说明实现过程。

## 1. 数据库设计

### 1.1 notification_template（通知模板表）

模板表沿用原有字段，示例值如下：

| 字段 | 示例值 | 说明 |
|---|---|---|
| `code` | `POST_LIKE` | 模板编码 |
| `category` | `interaction` | 通知分类 |
| `title_tpl` | `{sender_name} 赞了你的帖子` | 普通标题模板 |
| `body_tpl` | `NULL` | 普通内容模板 |
| `link_tpl` | `/posts/{post_id}` | 跳转链接模板 |
| `agg_key_tpl` | `post_like:{post_id}` | 聚合键模板 |
| `agg_title_tpl` | `{sender_names}等{count}人赞了你的帖子` | 聚合标题模板 |

聚合相关字段的规则：

| 字段 | 规则 |
|---|---|
| `agg_key_tpl` | 为 `NULL` 时不支持聚合；不为 `NULL` 时支持聚合 |
| `agg_title_tpl` | 定义聚合后的标题 |

### 1.2 notification（通知表）

一条记录代表用户看到的一条通知。以下是 `notification` 的建表语句，包含聚合所需的字段与索引。

```sql
CREATE TABLE notification (
    id              BIGINT NOT NULL,
    user_id         BIGINT NOT NULL COMMENT '接收用户ID',

    template_code   VARCHAR(64) NOT NULL COMMENT '模板编码',
    category        VARCHAR(32) NOT NULL COMMENT '通知分类',

    title           VARCHAR(255) NOT NULL COMMENT '通知标题',
    content         VARCHAR(1024) DEFAULT NULL COMMENT '通知内容',
    link            VARCHAR(512) DEFAULT NULL COMMENT '跳转链接',

    sender_id       BIGINT DEFAULT NULL COMMENT '触发用户ID',
    sender_type     VARCHAR(16) NOT NULL DEFAULT 'user' COMMENT '发送者类型',

    aggregate_key   VARCHAR(128) DEFAULT NULL COMMENT '聚合键',
    aggregate_count INT NOT NULL DEFAULT 1 COMMENT '聚合数量',
    last_event_time DATETIME DEFAULT NULL COMMENT '最近事件时间',

    is_read         TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否已读',
    read_time       DATETIME DEFAULT NULL COMMENT '阅读时间',

    create_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    PRIMARY KEY (id),
    KEY idx_user_read_time (user_id, is_read, create_time),
    KEY idx_user_aggregate (user_id, aggregate_key)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 1.3 notification_event（通知事件表）

`notification_event` 记录每一次实际发生的事件，建表语句如下。

```sql
CREATE TABLE notification_event (
    id              BIGINT NOT NULL,
    notification_id BIGINT NOT NULL COMMENT '所属通知ID',

    source_event_id BIGINT NOT NULL COMMENT '原始业务事件ID',
    sender_id       BIGINT DEFAULT NULL COMMENT '事件触发用户ID',

    create_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    PRIMARY KEY (id),
    UNIQUE KEY uk_source_event (source_event_id),
    KEY idx_notification_id (notification_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

`source_event_id` 用于防止同一条业务事件重复聚合，例如点赞表 `post_like` 中的记录 ID。

## 2. 聚合消息的实现流程

以用户 A 发布的帖子 1001 被张三、李四、王五分别点赞为例。

### 2.1 处理步骤

1. 事件产生：张三、李四、王五各点赞帖子 1001 一次。
2. 计算聚合键：`post_like:1001`。
3. 查找已有聚合通知：根据接收用户 + 聚合键 + 时间窗口查找。
4. 写入 `notification_event`：每次点赞都记录一条原始事件。
5. 更新 `notification`：更新数量、标题和最近事件时间。

### 2.2 最终结果

采用聚合通知时，用户 A 的 `notification` 表中只有 **1 条消息**，而不是 3 条。

## 3. 示例数据

对应的表数据如下。

### 3.1 notification 表

| `id` | `user_id` | `aggregate_key` | `aggregate_count` | `title` |
|---|---|---|---|---|
| 10001 | A | `post_like:1001` | 3 | 张三、李四、王五等 3 人赞了你的帖子 |

### 3.2 notification_event 表

| `id` | `notification_id` | `sender_id` |
|---|---|---|
| 1 | 10001 | 张三 |
| 2 | 10001 | 李四 |
| 3 | 10001 | 王五 |

两张表的关系：`notification` 中 1 条聚合消息，对应 `notification_event` 中 3 条原始事件。

## 4. 后续点赞

如果后来赵六又点赞：

- `notification` 仍然是 1 条。
- `aggregate_count` 更新为 4。
- `notification_event` 增加 1 条。

## 5. 聚合窗口

如果超过聚合时间窗口，例如 10 分钟，则可以创建第二条 `notification`，不再更新原来的消息。
