## 1. `.pnpm` 虚拟存储目录

`.pnpm` 是 pnpm 在当前项目 `node_modules` 目录下创建的虚拟存储目录（Virtual Store Directory）。

### 1.1 设置 `.pnpm` 的原因

在 npm v3+ 中，所有依赖被扁平化提升到顶层 `node_modules`，导致幽灵依赖（即代码可以使用未声明的间接依赖）。

为此，pnpm 采用以下策略：

- 顶层 `node_modules` 仅放置 `package.json` 中写明的直接依赖。
- 顶层 `node_modules` 中的直接依赖均为软链接。
- `.pnpm` 统一以展开形式放置直接依赖和间接传递依赖。
- `.pnpm` 通过精确软链接串联上述依赖。

### 1.2 目录命名与结构

`.pnpm` 目录采用扁平结构，每个包均使用 `包名@版本号` 规则命名。

以下代码展示 `.pnpm` 的目录结构：

```plaintext
node_modules/
├── .pnpm/
│   ├── axios@1.6.0/
│   │   └── node_modules/
│   │       ├── axios/                  <-- 这里的文件是通过硬链接指向全局 Store
│   │       └── follow-redirects/ ----> 软链接到：../../follow-redirects@1.15.0/node_modules/follow-redirects
│   │
│   ├── follow-redirects@1.15.0/
│   │   └── node_modules/
│   │       └── follow-redirects/
│   │
│   └── lodash@4.17.21/
│       └── node_modules/
│           └── lodash/
│
├── axios -> .pnpm/axios@1.6.0/node_modules/axios
```

## 2. 软链接

符号链接（Symbolic Link，简称软链接 / Symlink）类似于快捷方式：

- 记录并保存目标文件或目录的路径字符串指针。
- 本身仅占用几个字节到几十个字节。
- 计算目录大小时，默认不计入软链接所指向的目标文件大小。

## 3. 硬链接

### 3.1 硬链接定义

硬链接（Hard Link）指多个文件名同时指向底层磁盘上的同一个数据块（同一个 inode）。

- 软链接（快捷方式）：类似于一张写了地址的纸条。
- 硬链接（多重别名）：类似于房子开了两扇完全一样的大门。

### 3.3 使用硬链接的原因

全局 Store 到项目之间使用硬链接而非软链接，原因如下：

#### 防止误改全局源码

若项目直接软链接到全局 Store，开发者改动 `node_modules` 中的代码会篡改全局 Store 源文件，进而影响引用该 Store 的全部项目。硬链接结合操作系统机制与 Store 文件权限控制，可以有效隔离全局状态与项目操作。

#### 保持稳定不怕路径变动

当目标路径变动时，软链接会失效并形成死链。硬链接直接锚定底层 inode，只要底层数据块存在，硬链接指向的文件访问就不会失效。

## 4. 引用计数机制

硬链接在操作系统层面本质上是引用计数器。

### 4.1 全局 Store 保留引用的原因

全局 Store 自行保留一份文件指针（引用）的原因：全局 Store 一旦失去引用，pnpm将不再具备全局缓存能力。

### 4.2 引用计数变化过程

pnpm 下载文件存入全局 Store 并创建项目硬链接时，物理数据块（inode）的链接计数为 `2`。

当执行 `rm -rf node_modules` 或删除项目硬链接文件时，操作系统执行以下动作：

1. 抹掉当前项目目录下的文件名指针。
2. 将数据块引用计数从 `2` 减为 `1`。

只有当引用计数归零（变成 `0`）时，操作系统才会释放磁盘空间并抹除底层数据。只要全局 Store 仍保留硬链接，引用计数至少为 `1`，物理数据就不会丢失。

### 4.3 全局 Store 文件清理时机

删除项目的 `node_modules` 不会影响全局 Store。但在卸载旧项目后，全局 Store 可能残留不再被任何项目引用的孤儿文件。

以下命令用于清理全局 Store 中不再被任何项目引用的孤儿文件：

```bash
pnpm store prune
```

执行该命令时，pnpm 会扫描全局 Store 并检查每个文件的硬链接计数。对于仅由全局 Store 自身引用、且没有任何本地项目链接的文件，pnpm 会将其从全局 Store 中物理删除。
