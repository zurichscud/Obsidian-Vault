## 1. 强缓存

### 1.1 定义

**强缓存**是 HTTP 缓存体系中最快的一种机制。当客户端请求某个资源时，浏览器会先检查本地缓存；一旦命中强缓存，**浏览器完全不向服务器发送任何网络请求**，而是直接从本地内存或硬盘中读取资源。

### 1.2 命中表现

在浏览器开发者工具的 Network 面板中，强缓存通常体现为：

- 状态码显示为 `200 OK`
- Size 列显示为 `(from memory cache)` 或 `(from disk cache)`
- Time 列耗时通常为 **0 ms**

### 1.3 控制字段

强缓存完全由服务端在资源初次下发时的响应头控制，主要涉及两个字段：

| 响应头字段                              | 引入规范           | 核心机制                                                             | 特点 / 缺点                                      |
| ---------------------------------- | -------------- | ---------------------------------------------------------------- | -------------------------------------------- |
| `Cache-Control: max-age=<seconds>` | HTTP/1.1（现代标准） | **相对时间**（秒），表示资源自获取后的有效时长。例如 `max-age=31536000` 表示一年内有效。         | **绝对优先**，不受客户端系统时间偏差影响。                      |
| `Expires`                          | HTTP/1.0（历史遗留） | **绝对时间**（GMT 格式时间戳）。例如 `Expires: Wed, 21 Oct 2026 07:28:00 GMT`。 | 容易受客户端本地系统时间被篡改或不准确的影响，可能导致缓存**提前失效或长期不失效**。 |

### 1.4 优先级规则

当 `Cache-Control` 的 `max-age` 与 `Expires` 同时存在时，`Cache-Control` **具有更高优先级**，`Expires` 会被直接忽略。

### 1.5 判断流程

1. **发起请求**：用户在页面中加载静态文件（如 `<script src="bundle.js">`）或进行路由跳转。
2. **检查新鲜度**：
    - 计算该资源在本地的“年龄”（当前时间 - 资源接收时间）。
    - 对比响应头中的 `max-age`。
3. **分流处理**：
    - **未过期（命中强缓存）**：直接从内存或磁盘读取文件，返回 `200 (from cache)`，**网络请求数为 0**。
    - **已过期（强缓存失效）**：浏览器带着上次的 `ETag` 或 `Last-Modified` 向服务器发起网络请求，**进入协商缓存流程**。

## 2. 协商缓存

### 2.1 机制

当强缓存失效（超过 `max-age`）或被显式跳过（配置了 `Cache-Control: no-cache`）时，客户端不会盲目下载完整资源，而是携带缓存标识向服务器发起“询问”。

如果资源未变动，服务器返回轻量的 `304 Not Modified`，通知客户端直接复用本地文件；若已变动，则返回 `200 OK` 并下发全新内容。

### 2.2 `If-None-Match` 的触发链路

浏览器要自动带上 `If-None-Match`，必须满足一条完整的链路。

1. **首次请求已收到并存储了 `ETag`**

   浏览器第一次请求某个资源（如静态文件或 GET 接口）时，服务器的响应头中必须包含 `ETag`（例如 `ETag: "v1.2.0"`）。浏览器接收后，会将该响应体连同 `ETag` 一并持久化到本地 HTTP 缓存区。

2. **本地缓存被判定需要重新验证**

   当再次发起针对该 URL 的请求时，只要满足以下任一情况，浏览器就会自动唤起协商缓存：

    - 上次响应设置了 `Cache-Control: no-cache`（强制每次使用前验证）。
    - 上次响应设置的 `max-age` 已经超时失效（强缓存过期）。
    - 用户在页面上触发了**常规刷新**（按 `F5`、点击地址栏刷新按钮或 `Cmd+R`）。

3. **自动注入请求头**

   在发出真实 HTTP 请求的瞬间，浏览器底层网络模块会自动从缓存数据库中取出上次暂存的 `ETag` 值，将其赋值给 `If-None-Match` 随请求发送至服务端。

   以下为该请求发往服务端时的样子，`If-None-Match` 中携带的正是上次暂存的 `ETag` 值：

   ```http
   GET /api/v1/menus HTTP/1.1
   Host: example.com
   If-None-Match: "v1.2.0"
   ```
