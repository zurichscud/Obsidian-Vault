## 1. 发展历程

| 方式 | 特点 |
| --- | --- |
| `XMLHttpRequest` | 老式 API，基于回调，写法繁琐，了解即可 |
| `fetch` | 现代标准，基于 Promise，浏览器和 Node 18+ 都内置 |
| `axios` 等库 | 封装了拦截器、自动 JSON 转换、超时等，用起来更省心 |

## 2. fetch 基本用法

### 2.1 GET 请求

GET 请求示例：

```js
const res = await fetch('https://api.example.com/users');
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const data = await res.json();
```

### 2.2 POST 请求（JSON）

POST 请求（JSON）示例：

```js
const res = await fetch('https://api.example.com/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'Tom' }),
});
const data = await res.json();
```

### body

`fetch` 的 `body` 只接受这几种类型：

- `string`
- `FormData`
- `URLSearchParams`
- `Blob` / `ArrayBuffer` / TypedArray
- `ReadableStream`

传普通对象时，它会被**强制调用 `toString()`**，变成 `"[object Object]"`：

```js
fetch('/api', {
  method: 'POST',
  body: { name: 'Tom' },   // 实际发出去的是 "[object Object]"
});
```

服务端收到的就是这个无意义的字符串。

正确写法：
```js
fetch('/api', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'Tom' }),
});
```

## 3. 最容易踩的坑

1. **`fetch` 遇到 404 / 500 不会抛错**，只有网络故障才 reject，所以必须手动检查 `res.ok`。
2. **响应体只能读取一次**，重复调用 `res.json()` 会报错，需要时用 `res.clone()`。
3. **默认不带 Cookie 跨域**，需要设置 `credentials: 'include'`。
4. **`fetch` 没有内置超时**，需要自己用 `AbortController` 实现。
5. fetch 只负责传输字节，序列化和反序列化都由你来做。

## 4. 取消请求与超时

用 `AbortController` 取消请求，并设置 5 秒超时：

```js
const controller = new AbortController();
const timer = setTimeout(() => controller.abort(), 5000);

try {
  const res = await fetch(url, { signal: controller.signal });
  const data = await res.json();
} catch (err) {
  if (err.name === 'AbortError') console.log('请求被取消或超时');
  else throw err;
} finally {
  clearTimeout(timer);
}
```

现代写法更简洁：`fetch(url, { signal: AbortSignal.timeout(5000) })`。

典型场景：搜索框输入时，取消上一次未完成的请求，避免旧结果覆盖新结果（竞态问题）。

## 5. 封装一个实用的请求函数

以下函数封装 `fetch`，统一处理请求头、JSON 序列化和错误状态码：

```js
async function request(url, options = {}) {
  const res = await fetch(url, {
    headers: { 'Content-Type': 'application/json', ...options.headers },
    ...options,
    body: options.body ? JSON.stringify(options.body) : undefined,
  });
  if (!res.ok) {
    const error = new Error(`HTTP ${res.status}`);
    error.status = res.status;
    throw error;
  }
  return res.status === 204 ? null : res.json();
}
```

## 6. fetch 的 `res`（Response 对象）

### 6.1 它是什么

`await fetch(url)` 返回的是一个 **`Response`** 对象。注意：fetch 的 Promise 在**收到响应头**时就已经 resolve，此时响应体可能还没下载完。所以 `res` 的元信息可以立刻读，响应体需要再异步读取。

以下示例发起一次请求并取得 `res`：

```js
const res = await fetch('/api/users');
```

### 6.2 常用属性

| 属性               | 含义                    | 示例                                |
| ---------------- | --------------------- | --------------------------------- |
| `res.ok`         | 状态码是否在 200–299        | `true`                            |
| `res.status`     | 状态码                   | `200`、`404`                       |
| `res.statusText` | 状态文本                  | `"OK"`、`"Not Found"`              |
| `res.headers`    | 响应头（`Headers` 对象）     | `res.headers.get('content-type')` |
| `res.url`        | 最终请求的 URL（重定向后）       |                                   |
| `res.redirected` | 是否发生过重定向              | `false`                           |
| `res.type`       | 响应类型                  | `"basic"`、`"cors"`、`"opaque"`     |
| `res.body`       | 响应体的 `ReadableStream` |                                   |
| `res.bodyUsed`   | 响应体是否已被读取             | `false`                           |

### 6.3 读取响应体的方法

都返回 Promise，**只能选一个调用，且只能读一次**：

```js
await res.json();         // 解析为 JS 对象
await res.text();         // 纯文本
await res.blob();         // 二进制文件（图片、下载文件）
await res.arrayBuffer();  // 原始字节
await res.formData();     // 表单数据
```

连续读取两次会报错：

```js
const data = await res.json();
const again = await res.json(); // TypeError: body stream already read
```

需要读两次时用 `res.clone()`：

```js
const copy = res.clone();
const json = await res.json();
const text = await copy.text();
```

### 6.4 响应头的读取

读取响应头的方法如下：

```js
res.headers.get('Content-Type');       // 不区分大小写
res.headers.has('X-Token');

for (const [key, value] of res.headers) {
  console.log(key, value);
}
```

**注意：** 跨域请求时，浏览器只暴露少数“安全”响应头（如 `Content-Type`、`Cache-Control`）。想读自定义头，服务端必须设置 `Access-Control-Expose-Headers`。

### 6.5 流式读取

`res.body` 是 `ReadableStream`，可以边下载边处理：

```js
const res = await fetch('/stream');
const reader = res.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  console.log(decoder.decode(value, { stream: true }));
}
```

下面的示例按已下载字节数计算下载进度：

```js
const total = Number(res.headers.get('Content-Length'));
let loaded = 0;
const reader = res.body.getReader();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  loaded += value.length;
  console.log(`${((loaded / total) * 100).toFixed(1)}%`);
}
```

## 7. fetch 的 `res` 与 Express 的 `res`

**两者没有代码层面的关系，只是名字一样。**

| 对比项 | Express 的 `res` | fetch 的 `res` |
| --- | --- | --- |
| 所在位置 | 服务端（Node.js） | 客户端（浏览器 / Node 18+） |
| 类型 | `http.ServerResponse` 的增强版 | 标准的 `Response` 对象 |
| 角色 | **构造并发送**响应 | **接收并读取**响应 |
| 来源 | 框架传给路由回调 | `await fetch()` 的返回值 |
