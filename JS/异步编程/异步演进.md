## 1. 回调函数

早期 JavaScript 处理异步（如 `fs.readFile`、`setTimeout`、`XMLHttpRequest`）的唯一方式是传入一个函数，等待底层操作完成时调用。

下面是一个 Node.js 风格的 Error-First Callback 示例：

```js
// Node.js 风格的 Error-First Callback
getUser(userId, (err, user) => {
  if (err) return handleError(err);
  getOrders(user.id, (err, orders) => {
    if (err) return handleError(err);
    getOrderDetails(orders[0].id, (err, details) => {
      if (err) return handleError(err);
      console.log(details);
    });
  });
});
```

核心痛点：

1. **回调地狱（Callback Hell）**：横向缩进扩散（Pyramid of Doom），代码难以阅读与维护。
2. **控制反转（Inversion of Control）**：执行时机完全交给第三方回调（可能被调用 0 次、多次，或异步变同步），缺乏保障。
3. **错误处理支离破碎**：外层的 `try...catch` 无法捕获异步回调中抛出的异常，必须在每个回调里手动传递并检查 `err`。

## 2. Promise 规范（ES6）

Promise 是一种“承诺”机制，用标准化的状态机对象封装未来产生的值或失败原因，把控制权彻底扭转回来。

### 2.1 核心状态机与链式调用

Promise 拥有三种互斥且不可逆的状态：`pending`、`fulfilled`、`rejected`。`.then()` 每次返回一个新的 Promise，从而把嵌套调用摊平成链式调用：

```js
getUser(userId)
  .then(user => getOrders(user.id))
  .then(orders => getOrderDetails(orders[0].id))
  .then(details => console.log(details))
  .catch(err => handleError(err)); // 统一冒泡捕获
```

### 2.2 并发控制 API

- `Promise.all([p1, p2])`：全胜原则。全部成功才成功；任意一个 reject 直接失败。
- `Promise.race([p1, p2])`：赛跑原则。取第一个 settle（无论 resolve 还是 reject）的结果。
- `Promise.allSettled([p1, p2])`（ES2020）：宽容原则。等待全部完成，返回每个 promise 的状态和结果列表，不会被单个 reject 中断。
- `Promise.any([p1, p2])`（ES2021）：首胜原则。取第一个 resolve 的结果；若全部失败则返回 `AggregateError`。

### 2.3 局限性

- 相比于命令式代码，依然要通过链式 `.then()` 传递结果。多步骤共享上下文时（如既要用到 `user` 又要用到 `details`），代码不够直观。
- 无法原生取消，需结合后来的 `AbortController`。

## 3. Async / Await（ES2017）

- `async` 函数隐式返回一个 `Promise`。
- `await` 暂停当前协程，等待右侧 Promise 敲定（进入微任务队列），再解包其值并恢复执行。

示例用一个 `async` 函数串联多个 `await`，并用 `try...catch` 统一处理错误：

```js
async function fetchUserWorkflow(userId) {
  try {
    const user = await getUser(userId);
    const orders = await getOrders(user.id);
    const details = await getOrderDetails(orders[0].id);
    return details;
  } catch (err) {
    // 恢复了熟悉的同步错误处理模型
    handleError(err);
  }
}
```
### 3.1 并发陷阱与最佳实践

无依赖关系的异步操作不要写成顺序 `await`，否则会退化为串行阻塞：

```js
// 错误示范：串行等待，总耗时为两者之和
const user = await fetchUser();
const config = await fetchConfig();

// 正确姿势：并行发起，组合等待
const [user, config] = await Promise.all([fetchUser(), fetchConfig()]);
```

## 4. 现代演进与补充能力

### 4.1 Top-level Await

在 ES Modules（ESM）模块顶层可以直接使用 `await`，无需包裹 `async IIFE`。常见用途是模块动态导入、配置初始化或资源预加载：

```js
// module.js
export const config = await fetch('/api/config').then(r => r.json());
```

### 4.2 请求与异步任务中断

`AbortController` 为 Promise 体系补齐“取消操作”的能力：

```js
const controller = new AbortController();
fetch('/long-polling', { signal: controller.signal });

// 主动中断任务
controller.abort();
```
