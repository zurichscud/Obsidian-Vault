发布者只管"发消息"，订阅者只管"收消息"，两者互相不认识，通过一个中间人（事件中心）联系。

### 2. 为什么需要它

没有发布订阅时，模块之间是**直接调用**：

js

```js
function login() {
  // 登录成功后，要通知一堆模块
  updateHeader();
  loadCart();
  sendAnalytics();
  showWelcome();
}
```

问题：`login` 必须认识所有下游模块，每多一个需求就要改 `login`，**耦合严重**。

用发布订阅后：

js

```js
function login() {
  bus.emit('login', user);   // 只管广播，不关心谁在听
}

bus.on('login', updateHeader);
bus.on('login', loadCart);
bus.on('login', sendAnalytics);
```

新增需求只需要再加一个 `bus.on(...)`，`login` 完全不用改。

### 3. 三个核心角色

|角色|职责|对应方法|
|---|---|---|
|事件中心|存储"事件名 → 回调列表"的映射||
|订阅者|登记想听的事件和回调|`on` / `subscribe`|
|发布者|触发事件，把数据传给所有回调|`emit` / `publish`|
|取消订阅|移除回调，避免内存泄漏|`off` / `unsubscribe`|

### 4. 手写一个 EventEmitter

js

```js
class EventEmitter {
  constructor() {
    this.events = {};  // { 事件名: [回调1, 回调2, ...] }
  }

  on(type, fn) {
    (this.events[type] ||= []).push(fn);
    return this;
  }

  off(type, fn) {
    this.events[type] = (this.events[type] || []).filter(f => f !== fn);
    return this;
  }

  once(type, fn) {
    const wrapper = (...args) => {
      fn(...args);
      this.off(type, wrapper);
    };
    return this.on(type, wrapper);
  }

  emit(type, ...args) {
    (this.events[type] || []).slice().forEach(fn => fn(...args));
    return this;
  }
}
```

- **`on`**：登记，告诉事件中心"这个事件发生时，请执行我这个函数"。
- **`emit`**：触发，通知事件中心"这个事件发生了"，所有登记过的函数随即被执行。
- **`off`**：注销，告诉事件中心"这个函数我不再需要通知了"。
- **`once`**：订阅一个事件，但只响应第一次。触发过一次后自动注销，之后再 `emit` 也不会再执行。

```js
const bus = new EventEmitter();

const onLogin = user => console.log('欢迎', user.name);
bus.on('login', onLogin);
bus.once('login', () => console.log('只提示一次'));

bus.emit('login', { name: 'Tom' });
// 欢迎 Tom
// 只提示一次

bus.emit('login', { name: 'Amy' });
// 欢迎 Amy

bus.off('login', onLogin);  // 取消订阅
```
