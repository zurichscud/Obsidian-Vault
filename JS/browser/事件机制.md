## 1. 事件机制是什么

浏览器在发生点击、输入、滚动、加载完成等情况时，会创建一个**事件对象**，沿着 DOM 树传递，并执行所有登记过的**监听函数**。

## 2. 绑定与移除事件

下面的示例展示了推荐的绑定与移除写法，以及两种不推荐的替代写法：

```js
// 推荐写法
el.addEventListener('click', handler);
el.removeEventListener('click', handler);

// 其他写法（不推荐）
el.onclick = handler;                 // 同一事件只能绑定一个，后者覆盖前者
// <button onclick="handler()">       // 行内写法，HTML 与 JS 耦合
```

- `addEventListener` 可以给同一事件绑定多个函数，按绑定顺序执行。
- 移除时必须传入**同一个函数引用**。匿名函数无法移除。
- 第三个参数可以是配置对象：
    - `once: true`：只触发一次，之后自动移除。
    - `capture: true`：在捕获阶段触发。
    - `passive: true`：承诺不会调用 `preventDefault()`，浏览器可以放心优化滚动性能。
    - `signal`：传入 `AbortController` 的 signal，调用 `abort()` 可一次性移除多个监听。
### passive
`passive` 是 `addEventListener` 第三个参数（配置对象）里的一个选项：

```js
el.addEventListener('touchmove', handler, { passive: true });
```

设为 `true`，就是向浏览器**承诺：这个监听器里不会调用 `preventDefault()`**。

> [!note] 为什么需要它
> 以滚动为例。浏览器处理触摸或滚轮事件时，有一个两难：
> - 监听器**可能**调用 `preventDefault()` 来取消滚动。
>- 所以浏览器在不确定的情况下，必须**先等监听器执行完**，才能决定页面要不要滚。
>- 如果监听器里的代码比较慢，页面滚动就会卡顿、掉帧。
>
>声明 `passive: true` 后，浏览器知道这个监听器不会取消滚动，就可以**不等监听器，直接开始滚动**，监听器与滚动并行执行，滚动更流畅。



## 3. 事件对象

| 名称                        | 含义                        |
| ------------------------- | ------------------------- |
| `e.type`                  | 事件类型，如 `'click'`          |
| `e.target`                | **真正触发**事件的元素             |
| `e.currentTarget`         | **当前正在执行监听器**的元素（绑定监听的那个） |
| `e.preventDefault()`      | 阻止默认行为（如链接跳转、表单提交）        |
| `e.stopPropagation()`     | 阻止事件继续向其他元素传播             |
| `e.key` / `e.code`        | 键盘事件：按下的键                 |
| `e.clientX` / `e.clientY` | 鼠标事件：相对视口的坐标              |

## 4. 事件流：捕获、目标、冒泡

### 4.1 三个阶段

一个事件的传播分三个阶段：

1. **捕获阶段（capture）**：从 `window` → `document` → ... → 目标元素的父级，自上而下。
2. **目标阶段（target）**：到达目标元素。
3. **冒泡阶段（bubble）**：从目标元素 → 父级 → ... → `window`，自下而上。

### 4.2 默认监听器在冒泡阶段执行

“默认监听器在冒泡阶段执行”是指：用 `addEventListener` 绑定事件且不传第三个参数（或传 `false`）时，事件处理函数在冒泡过程中触发，而不是在向下寻找目标的过程中触发。

### 4.3 中断传播

`event.stopPropagation()` 用于阻止事件在 DOM 树中继续向**后续节点**传播，具体效果取决于调用所在的阶段：

- **在冒泡阶段调用**：阻止事件继续向上冒泡到父元素；当前元素上绑定的其他同类监听器**仍会执行**。
- **在捕获阶段调用**：阻止事件继续向下捕获到子元素，事件直接终止。

## 5. 事件委托

### 5.1 原理与写法

**原理**：利用冒泡，把监听器绑在父元素上，由父元素统一处理子元素的事件，通过 `e.target` 判断是谁触发的。

下面的示例在父元素 `list` 上监听点击，再用 `closest()` 找到被点击的 `li`：

```js
list.addEventListener('click', (e) => {
  const item = e.target.closest('li');//找到需要的子元素
  if (!item || !list.contains(item)) return;
  console.log('点击了：', item.textContent);
});
```

### 5.2 优点

- 只需一个监听器，节省内存。
- 之后动态添加的子元素**自动生效**，不用重新绑定。

### 5.3 注意事项

- 依赖冒泡，不冒泡的事件（如 `focus`）不能直接委托。
- 中间层若调用了 `stopPropagation()`，委托会失效。
- 用 `closest()` 而不是直接比较 `e.target`，因为点击的可能是 `li` 里的子标签。

## 6. 默认行为

浏览器对某些事件有内置行为，如点击 `<a>` 跳转、点击提交按钮提交表单。

下面的示例在提交时阻止页面刷新，交给 JS 自己处理：

```js
form.addEventListener('submit', (e) => {
  e.preventDefault(); // 阻止页面刷新，自己用 JS 处理
});
```

## 7. 自定义事件

下面的示例先监听一个自定义事件，再用 `dispatchEvent` 触发它：

```js
// 监听
el.addEventListener('user-login', (e) => {
  console.log(e.detail.name);
});

// 触发
el.dispatchEvent(new CustomEvent('user-login', {
  detail: { name: 'Tom' },
  bubbles: true,   // 默认不冒泡，需要时要显式开启
}));
```

用途：组件之间通信、实现发布订阅，不依赖用户操作也能触发事件。

## 常见事件
### 1. 鼠标事件

|事件|触发时机|冒泡|
|---|---|---|
|`click`|点击（按下并在同一元素上松开）|是|
|`dblclick`|双击|是|
|`mousedown` / `mouseup`|鼠标按键按下 / 松开|是|
|`mousemove`|鼠标在元素上移动（高频）|是|
|`mouseover` / `mouseout`|鼠标进入 / 离开元素**及其子元素**|是|
|`mouseenter` / `mouseleave`|鼠标进入 / 离开元素本身，不因子元素触发|**否**|
|`contextmenu`|右键菜单弹出前|是|
|`wheel`|滚轮滚动|是|

要点：

- `mouseover/out` 在鼠标穿过子元素时会反复触发，做悬停效果通常用 `mouseenter/leave`。
- `contextmenu` 里调用 `preventDefault()` 可以自定义右键菜单。
- 常用属性：`e.clientX/clientY`（相对视口）、`e.pageX/pageY`（相对页面）、`e.button`（0 左键、1 中键、2 右键）、`e.ctrlKey/shiftKey/altKey/metaKey`。

### 2. 键盘事件

|事件|触发时机|
|---|---|
|`keydown`|按键按下（按住不放会持续触发）|
|`keyup`|按键松开|
|`keypress`|**已废弃**，不要再用|

js

```js
document.addEventListener('keydown', (e) => {
  if (e.key === 'Enter' && !e.isComposing) { /* ... */ }
  if (e.ctrlKey && e.key === 's') {
    e.preventDefault();
    save();
  }
});
```

要点：

- `e.key` 是按键的字符含义（`'a'`、`'Enter'`、`'Escape'`），`e.code` 是物理按键位置（`'KeyA'`、`'Enter'`），做游戏快捷键用 `code`，做文字相关用 `key`。
- `e.repeat` 为 `true` 表示是按住不放产生的重复触发。
- 中文输入法组合输入时要判断 `e.isComposing`。

### 3. 表单与输入事件

| 事件                            | 触发时机                                | 冒泡    |
| ----------------------------- | ----------------------------------- | ----- |
| `input`                       | 值每次变化（实时）                           | 是     |
| `change`                      | 值改变并提交（文本框失焦或回车，checkbox/select 立即） | 是     |
| `submit`                      | 表单提交，绑定在 `<form>` 上                 | 是     |
| `reset`                       | 表单被重置                               | 是     |
| `focus` / `blur`              | 获得 / 失去焦点                           | **否** |
| `focusin` / `focusout`        | 同上，但**会冒泡**，适合事件委托                  | 是     |
| `select`                      | 文本被选中                               | 是     |
| `invalid`                     | 表单校验未通过                             | 否     |
| `compositionstart/update/end` | 输入法组合输入的开始 / 过程 / 结束                | 是     |
`<input>` 元素既有 `input` 事件，也有 `change` 事件：

- **`input` 事件**：值**每发生一次变化就触发**，实时的。
- **`change` 事件**：值**改变并且"提交"这次改变时才触发**，通常是失去焦点或按回车的时候。
### 4. 页面与资源事件

| 事件                        | 触发时机                        | 目标           |
| ------------------------- | --------------------------- | ------------ |
| `DOMContentLoaded`        | HTML 解析完成，DOM 树构建好（不等图片、样式） | `document`   |
| `load`                    | 页面及所有资源（图片、样式、脚本）加载完        | `window`     |
| `beforeunload`            | 页面即将关闭或刷新                   | `window`     |
| `unload`                  | 页面卸载（不推荐使用）                 | `window`     |
| `pagehide` / `pageshow`   | 页面隐藏 / 显示（包括前进后退缓存）         | `window`     |
| `visibilitychange`        | 标签页切到后台 / 回到前台              | `document`   |
| `resize`                  | 窗口大小变化                      | `window`     |
| `scroll`                  | 滚动（高频）                      | 元素或 `window` |
| `error`                   | 资源加载失败或脚本报错                 | 元素或 `window` |
| `hashchange` / `popstate` | URL 的 hash 变化 / 历史记录前进后退    | `window`     |
| `online` / `offline`      | 网络恢复 / 断开                   | `window`     |

要点：

- 想尽早操作 DOM，用 `DOMContentLoaded`，而不是 `load`。
- `visibilitychange` 比 `unload` 更可靠，适合在用户离开页面时上报数据或暂停视频、轮询。
- `load` 和 `error` 对图片等元素**不冒泡**，委托时要在捕获阶段监听。
- `scroll`、`resize` 属于高频事件，需要防抖或节流。
