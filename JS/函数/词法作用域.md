---
title: 词法作用域
---

词法作用域（Lexical Scope）：变量的作用域在代码书写（定义）的时候就已经确定了，和函数在哪里、怎么被调用无关。

## 1. 直观例子

先看一个例子：

```js
const x = 'global';

function outer() {
  const x = 'outer';
  function inner() {
    console.log(x);
  }
  return inner;
}

const fn = outer();
fn(); // 'outer'
```

`inner` 是在 `outer` 里**写出来**的，所以它查找 `x` 时，看的是**书写位置**的外层，即 `outer`，而不是调用它的地方（全局）。

## 2. 对比：动态作用域

如果 JS 是动态作用域，结果会不同：

```js
const x = 'global';

function foo() {
  console.log(x);
}

function bar() {
  const x = 'bar';
  foo();
}

bar(); // 词法作用域 输出 'global'，动态作用域输出'bar'
```

|        | 词法作用域            | 动态作用域            |
| ------ | ---------------- | ---------------- |
| 变量查找依据 | 函数**定义**的位置      | 函数**调用**的位置（调用栈） |
| 确定时机   | 编译 / 书写阶段        | 运行阶段             |
| 例子语言   | JS、Python、Java、C | Bash             |

上面的例子里 `foo` 定义在全局，所以它看到的 `x` 是全局的。如果是动态作用域，会输出 `'bar'`。**JS 的变量查找是词法作用域。**

## 3. 作用域链

查找变量时，先在当前作用域找，找不到就沿着**书写时的嵌套关系**逐层向外找，直到全局：

```js
const a = 1;
function f1() {
  const b = 2;
  function f2() {
    const c = 3;
    console.log(a, b, c); // 逐层向外查找:c → b → a
  }
  f2();
}
f1();
```

对应的作用域链：

```
f2 作用域 {c}  →  f1 作用域 {b}  →  全局作用域 {a}
```

每个函数在**创建时**就会记住自己的外层作用域（内部属性 `[[Environment]]`），调用时以此建立作用域链。

## 4. 词法作用域与闭包

闭包正是词法作用域的直接产物：函数即使在原作用域之外执行，依然能访问它**定义时**所在作用域的变量。

下面用计数器演示这一点：

```js
function counter() {
  let n = 0;
  return () => ++n;
}
const c = counter();
c(); // 1
c(); // 2  —— n 虽然在 counter 执行完后本应销毁,但被内部函数"记住"了
```
